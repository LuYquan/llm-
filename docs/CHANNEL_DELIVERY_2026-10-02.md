# 遥测业务读取与界面分发

本轮修复动画帧暂停时仍在入库的遥测被误判过期，以及订阅回调中新数据被清掉的问题。它是软件可靠性改进；实际 Windows 隐藏／最小化、原生串口、设备停机和长期采集仍待验收。

## 失效原因与取舍

原 ChannelStore 发现浏览器存在 `requestAnimationFrame` 后只安排动画帧，没有实现注释所说的后台计时器降级。未完成的帧句柄又阻止后续安排。原始缓冲、接收时间和版本继续更新，场景工作台却读取订阅副本，因而把界面通知停顿误认为串口断流。

隐藏页面可以不参加浏览器的渲染更新；计时器本身也可能被合并。依据是 [HTML 渲染更新规则](https://html.spec.whatwg.org/multipage/webappapis.html#update-the-rendering)。因此不能仅增加一个 timer 就承诺后台实时控制，也不能放宽遥测保护时间来掩盖调度延迟。

| 路径 | 本轮实现 | 保留边界 |
| --- | --- | --- |
| 业务最新值 | `observeLatest` 同步返回 detached point、真实入库时间、版本及该通道最后入库的 generation。没有建缓冲、快照或分发副作用；非有限值返回未就绪。 | 读取不刷新时间。断开连接或入库代次不同仍拒绝。主机入库时间不证明固件采样时间。 |
| 写入后参数回读 | 使用原始 observation，继续经过 written receipt、session／epoch、generation、写入前版本水位和接收时间检查。 | 同毫秒写入前数据不能确认本轮；新鲜旧参数也必须符合候选和容差。 |
| 显示通知 | rAF 与 timer 竞争，同一 ticket 先完成者取消另一方；明确支持句柄 0。 | 已排队的旧回调不能释放新 ticket；计时器仍不保证实时。 |
| 分发生命周期 | 显式 flush、clear 和最后取消订阅共享取消逻辑；回调前移走 dirty、记录发送时间，禁止同步重入，按订阅快照检查存续。 | 回调中新增样本留到下一轮；清空改变 generation 后中止旧批次；不同 fps 按最早期限调度。 |
| 部分清空 | 每通道保留实际入库 generation；batch 的当前 store generation 与 `updatedGenerations` 分开。 | 清一个通道不会把其它旧样本重新标为本代。其它通道再次入库才更新身份。 |

参数读取、回读确认、采集输出检查、运行保护、指标读取和新鲜度判定共用业务 helper。界面摘要与读数仍可节流；反馈窗口的配置签名、会话、代次、确认后边界及串级内环依据保持有效。

## 可执行的软件复核

`npm run test:widget` 包含 `tests/channel-dispatch.test.ts` 的 12 组确定性场景，直接运行实际 ChannelStore。覆盖原始身份、有限值、浅复制、部分清空、句柄 0、竞争与迟到回调、显式 flush、取消订阅、回调内写入／重入／清空／删除与新增订阅、异常隔离、多个 fps 期限以及参数回读关联。独立只读审查也执行当前 12 场景，并用错误的全局 generation 替换作为反例，验证检查能拒绝旧样本重新标记。

```powershell
npm run test:widget
npm run build
node tests/browser/background-delivery-harness.vite.mjs
```

浏览器打开 `http://127.0.0.1:5202/tests/browser/background-delivery-harness.html`。仅这个独立 origin 提供合成端口与本地脚本候选；使用实际 App、WebSerialTransport、session、解析 Worker 和自然入库。没有显式 `flushDispatch`、补造采样、回填时间或修改保护期限。

1. 连接夹具端口，打开 AI 辅助。展开当前参数设置，从本次遥测读取 PI 参数并核对基线，等待新的基线观察窗口。
2. 单独“截留全部 rAF”。记录新证据，确认通知经 timer 继续自然到达。
3. 再“截留订阅回调”，使界面副本停留在旧值。按实际 UI 生成候选、核对字节并发送，正常分支应由参数回传确认后完成评价。
4. 独立重载准备有界自动方式，核对保守基线并使下一次本地候选保持延迟。授权后记录 pending 请求，再“暂停合成 RX”。核对保护停止、HTTP 取消和没有参数写入；随后放行迟到响应，不能恢复执行。
5. 重载选择“参数回读超时”。仍接收旧参数的数值帧，确认应在配置的 1 秒期限后失败，没有评价或已确认参数。
6. 重载选择“写入后输出越界”。在实际 written receipt 后生成输出 11，显示副本仍为 1；原始保护应按上限 10 停止。

本轮保留的结果如下。新鲜度设置始终为 0.5 秒，观察窗口 0.7 秒，确认超时 1 秒，输出上限 10。字节流与本地响应是脚本输入，不证明控制对象或模型效果。

| 场景 | 实际保存结果 |
| --- | --- |
| rAF 单独暂停 | timer 自然通知继续，原始数据新鲜；取消了竞争中的帧。 |
| rAF 与订阅同时暂停 | 1 次参数写入、0 次 STOP；本轮参数回传确认，35 点反馈评价完成，误差 0.02。订阅副本过期而原始 observation 仍新鲜。 |
| 自动等待期间断流 | 0 次参数写入、1 次 STOP；HTTP 请求断开，放行迟到响应不执行。此轮从最后入库到 STOP 为 556 毫秒，是观测值，不是期限保证。 |
| 新鲜旧参数 | 1 次参数写入、1 次 STOP；确认超时，参数仍为旧值，没有评价。 |
| 新输出越界 | 1 次参数写入、1 次 STOP；原始值 11、显示副本 1，因上限越界停止，没有评价。 |
| 上次提交反证 | 从 `d35451a457952851d6d69f9f20367530380aad6b` 对应的 374 个已核实输入建立保存副本，复制同三份新夹具，独立 5203 运行。原始解析继续、订阅计数静止；执行旧候选误报过期，0 次参数写入、1 次 STOP。 |

停止后的 Vue 提示动画因夹具截留全部 rAF 而遮住记录按钮。负向分支在 STOP 已记录之后才恢复 rAF 以取得完整快照，订阅继续截留；本地验证脚本核对事件顺序。恢复帧不是解除发送锁定，也没有修改产品或保护设置。所有实际 App 记录的运行时错误为空。

完整记录、校验脚本、源码审查摘要和保留的早期失败在本地 `output/background-delivery-20261001/`；该目录不随源码上传。机器校验按文件哈希关联这些记录。构建和源码发布另以各自 source-inputs、manifest、产物哈希和 Git tree 建立关联，不能把新增源码倒签为上一构建已测。

## 仍需原生与设备验证

本轮 fixture 的 `document.visibilityState` 是 visible；“截留 rAF／订阅”是明确的合成调度条件，不能算实际浏览器隐藏或 Windows 最小化验收。原生 WebView2、Rust IPC、真实 UART、操作系统缓冲及实际硬件需分别测量；若实际入库或事件循环本身迟到，保持保护停止，不能靠旧值延续授权。

原生复核需绑定具体 EXE／源码、WebView2 版本、串口与固件，记录前台、隐藏、最小化及恢复的接收间隔、保护判定、写入回执、记录完整性和旧会话失效。设备独立看门狗、限幅和物理急停另行验证。软件 STOP 字节被本地写入不等于设备收到、执行或停机。

TypeSafe 仅用于本轮流程取舍说明；精确身份和调度状态由本地代码判断，Jev 调用 0 次，没有向外部判断服务发送源码或遥测。正式发行的许可证和严格 Rust 公告门槛仍待完成，见[路线图](ROADMAP.md)及[依赖记录](CONTROL_AND_DEPENDENCY_HARDENING_2026-10-01.md)。
