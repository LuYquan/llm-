# 主体流程数据一致性修复

日期：2026-10-01。场景 AI 重构、独立构建与对应 290 文件源码快照封存后，继续检查连接、字节、波形和录制回放主流程。本轮限定三个已复现问题，不重复审美评审，不改变设备权限或用户记录。

## 1. 一块多帧被波形时间戳去重覆盖

RawData u8 单通道一次输入 `01 02 03`，解析器得到 `[1,2,3]`，原 Web Serial 波形适配器却把同一块的相同接收时间当成同一帧，得到 `[3]`。Worker 和主线程兜底均存在此问题。原始字节另走记录路径，本例没有证明记录字节丢失。

`ParsedBatch` 现在可携带完整有序 `frames`。两个生产者保留解析帧；波形按帧顺序构列，多帧保持原主机到达时间，不再按时间去重。缺失和非有限值维持 NaN，命名通道按实际帧映射。旧 `samples` 契约保持兼容，session / epoch 过滤不变。flush、RESET 和协议 CONFIGURE 同步清理帧缓冲。

接收统计在有帧元数据时按实际帧数累计，仍按主机投递的一秒窗口显示吞吐量。相同到达时间不提供真实设备采样间隔，不能把这项修复或微秒单位当作设备时钟精度证据。FFT / 调参的时间质量门槛仍独立执行。

| 回归输入 | 修复前 | 修复后 |
| --- | --- | --- |
| fallback RawData 三帧 | `[[3]]` | `[[1,2,3]]` |
| fallback JustFloat `[[1,10],[2],[3,30]]` | `[[3],[30]]` | `[[1,2,3],[10,NaN,30]]` |
| 实际 Worker 两通道三帧 | `[[3],[30]]` | `[[1,2,3],[10,20,30]]` |
| 三帧吞吐统计 | 1 | 3 |

Web Serial 行为回归 30 项通过，包含实际 `demuxer.worker.ts` 在隔离 self / timer 环境执行、跨块残帧、坏浮点诊断、命名通道、空 samples / NaN、旧契约及缓冲清理。限定复核还发现 RESET 未清二进制解析器内部半帧，已补充 `binaryEngine.reset()`：u16 与 JustFloat 的 RESET 前半帧不能与之后的新数据拼接，新的完整帧仍可解析。真实波形结果通过 `ChannelStore.pushSeries → snapshot` 后继续完整保留 `[1,2,3]`。这些是 Node 软件证据，真实浏览器 Worker 和实际设备吞吐须另行验收。

## 2. 回放旧请求写入新选择

原逻辑在读取 A 时点击 B，B 因全局 loading 被跳过；A 返回后以 B 的解码器显示 A。使用实际 App 函数和真实解码器的内存复现得到 `readCalls=[A]`、`selected=B`、`page=A`，A 的文本 `1,2\n` 在 B 的 RawData 中变为 `[49,44,50,10]`。

新增 `RecordingReplayController`，App 的选择、关闭和读取委托给同一个控制器。每次选择/重开/关闭递增世代；新选择可以立即读取。请求捕获 sessionId、目录、epoch 与解码器，返回身份不匹配则拒绝并显示错误。旧成功、错误和 finally 不改变新选择；App 卸载使旧请求失效。只清理 App 内存回放状态，不调用存储删除或关闭传输，普通抽屉收起不卸载 App。

延迟 Promise 回归覆盖 A/B 两种返回顺序、旧错误、关闭、同 ID 重开、不同目录、sessionId / epoch 不匹配、正常跨页残帧、空页、重复点击及失败游标重试。修复后 `readCalls=[A,B]`，B 的页面和 `[7]` 样本在 A 迟到后保持一致。

浏览器当前源码正常流程也已执行：演示源 → 记录 → 停止 → 记录库 → 只读回放 → 关闭 → 断开。新测试记录 `web-1790785311392-5loc7m7n` 为模拟源，30,480 原始字节、1,451 块；回放显示三个通道各 1,451 点，共 4,353 个解析样本及原始首块字节。没有连接或写入物理串口，没有删除已有记录。延迟竞态由确定性回归复现，浏览器正常流程负责验证 App 接入。

## 3. 收发能力与界面选择一致

原编码选择只写入 localStorage，未传到 UTF-8 编码器或 Rust / Worker 解码器。GBK / GB2312 / ASCII 可选项没有实际效果。现改为显示真实的 UTF-8 文本编码，保留 HEX 字节发送和原始字节核对；保留既有存储键，不删除用户设置。发送格式提示从 ASCII 改为 UTF-8 文本 / HEX 字节。

现有统一编码器的中文 UTF-8、HEX、转义和换行测试通过；浏览器终端工具显示 UTF-8，GBK option 数量为 0。完整多字符集支持若未来实现，需要同时覆盖 TX、RX 跨块、原始记录及回放元数据，不能只增加一个下拉选项。
