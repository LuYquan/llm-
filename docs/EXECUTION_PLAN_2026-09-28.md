# LLM 串口可靠工作台改进执行计划

版本：1.0  
基线日期：2026-09-28；最近执行状态见 [实施台账](IMPLEMENTATION_PROGRESS_2026-09-28.md)  
产品方向：可靠串口与波形工作台，AI/调参作为增强能力  
目标平台：Windows 桌面优先；Web 保留核心串口、终端、波形和工程语义。

## 目标与约束

主链路为“设备字节 → 会话标识与 RX 序号 → 原始记录/协议解析 → 通道存储 → 波形、终端和分析 → 可选 AI/调参”。显示数据可以降采样；记录与分析不得将显示抽样冒充原始数据。使用 Vue、Tauri、Rust 和 uPlot，按阶段修复，不重写技术栈。

Windows 由 Rust 承担串口 I/O、连接生命周期、协议解析和磁盘记录；Web 由 Web Serial 与 Worker 承担相应职责，两端通过同一套黄金字节样本保持协议语义一致。AI 默认只提供结构化建议；任何设备写入都必须经过本地约束和明确授权。

本轮不扩展 TCP、UDP、BLE、CAN、多设备并发或云同步。真实串口、长时间采集、控制执行机构和附带 EXE 的原生验收均需单独记录证据，主机单测不能替代硬件验证。

## 核心契约

| 契约 | 最低字段 | 约束 |
|---|---|---|
| `ConnectionProfile` | 端口、波特率、数据位、校验、停止位、流控、信号策略、协议配置、配置版本 | 默认 115200、8N1、无流控；仅开放运行时实际支持的参数。 |
| `SessionIdentity` | `sessionId`、`epoch`、来源、配置版本 | 每次重连/协议重建变化；旧事件不得污染新会话。 |
| `RawChunk` | 会话、RX 序号、单调接收时间、原始字节 | 不先解码，不反推字节；接收时间与设备采样时间分开。 |
| `SampleBatch` | 会话、批次序号、稳定通道 ID、各样本时间和值、时间来源、质量标志 | 缺失值为空洞，不伪造有效测量；名称只作为元数据。 |
| `WriteRequest/Result` | 请求 ID、会话、来源、字节、配置版本、权限上下文；状态、字节数、时间、原因 | 状态区分 `queued/written/acknowledged/failed/canceled/superseded`；`written` 不等于设备确认。 |
| `AnalysisResult` | 来源会话/通道/区间、算法版本、参数、质量状态、结果或拒绝原因 | 前提不满足时返回未知/拒绝，不填造默认成功指标。 |
| `WorkspaceDocument` | 版本、连接/协议、布局、通道、命令、控件、试验与记录引用 | 不含 API Key、自动发送授权或活动会话权限。 |

## 跨功能行为规则

1. 画面暂停不停止采集；“停止采集”“暂停显示”“停止记录”各自独立并显示状态。
2. 断开和重连会终止周期发送、未完成命令及调参；重新连接不恢复旧发送授权。
3. 没有配置停止字节时不发送默认设备命令；软件停止仍需锁住普通队列、周期任务与调参。
4. 已进入操作系统/驱动的在途字节不可宣称撤回；用户界面区分队列、驱动写入和设备确认。
5. 数据时基明确分为设备时间、用户配置采样周期、主机接收时间；没有采样时钟不输出精确采样率结论。
6. 记录默认由用户启动；显示缓冲与磁盘会话分离。演示和回放不能访问物理发送器。
7. AI 默认只给候选和依据；命令或参数必须经本地 Schema、限幅和人工/试验状态机复核。

## 工作包与逐步执行

### T00：基线、恢复与验收台账

1. 记录分支、提交、已修改与未跟踪内容，建立可恢复源码检查点；禁止用 `git clean/reset` 或覆盖未知用户改动。
2. 记录现有 EXE 的版本、大小和 SHA-256；开发构建使用独立输出目录，不覆盖 `release/data` 或现有发布包。
3. 将本执行计划、问题编号 F01–F17、每包测试与证据状态保存在仓库文档中。
4. 为自动化测试分配独立数据根目录，不接触用户真实记录。
5. 建立统一的类型检查、前端单测、Rust 测试和构建入口；每个问题记录源码、模拟、浏览器、原生、硬件证据等级。

完成标准：源代码及现有发布物可恢复；测试数据不会污染正式记录；每个发现都能映射到代码、测试或人工验收。

### T01：删除错误成功与伪造指标（F06、F11、F12、F16）

1. 修复调参手动候选流程读取 Vue `ref.value` 的条件，并覆盖真实组件动作路径。
2. SendGate 没有发送器、断线或拒绝时必须失败；同控件旧任务被替代时返回 `superseded`。
3. 删除从阻尼比伪造相位裕度的计算；没有有效结果时显示“未计算”。
4. 仿真或分析失败时返回无效及原因，不允许默认 `is_stable: true`。
5. 断开/未收到数据时速率显示 `—`；配置采样率与观察到的接收速率分开显示。
6. 在驱动写入回执和 ACK 链路完成前禁用调参执行，保留编辑、审阅和历史。
7. 隐藏未实现的网络连接入口；旧工程中的网络字段保留但明确不支持。

完成标准：无设备写入、无有效分析时不会显示成功/稳定；候选可生成但不能绕过执行门禁。

### T02：连接配置、会话身份与重连（F02、F03）

1. 用唯一 `ConnectionProfile` 驱动顶栏、连接面板、会话服务和 Rust/Web Serial。
2. 仅显示并传递驱动实际支持的数据位、校验、停止位和流控；连接后回显有效参数。
3. 连接/断开统一走 Transport；每个事件带 `sessionId/epoch`，丢弃旧会话回调。
4. Web Worker Channel 断开时释放、重连时重建；新旧事件降级只能消费一种来源并按序号去重。
5. 等待读写任务与句柄真正结束后再更新断开状态；清除端口探测、定时器和过期分析状态。
6. 设备重新出现只提示用户；不同设备不继承先前的发送授权。
7. 保存连接参数时避免启动默认值覆盖已保存配置。

完成标准：重复连接/断开无多重订阅和跨会话数据；拔插状态与驱动一致。100 次循环和真实驱动参数需要原生验收。

### T03：原始字节与协议解析（F01、F04）

1. Rust 使用 byte chunk 读取，先赋序号、会话和单调接收时间并交给记录器，之后才解析。
2. FireWater 支持 CSV、Teleplot 与文本日志；JustFloat 处理跨块、粘包、残包、非法浮点与重同步。
3. RawData 默认只保留/显示原始字节；启用数值解析时才要求格式、字节序和通道数。
4. CustomFrame 用用户配置的帧头、固定负载、数值格式、校验算法参数及校验字节序；不展示未经实现的伪示例。
5. 协议配置通过明确的应用动作生效，切换时递增配置代次、清除解析残留并记入事件。
6. 最大帧长 64 KiB；超限计入丢弃/重同步诊断，但原始记录保留实际收到的数据。
7. 输出诊断项：RX 字节、有效帧、校验失败、重同步、丢弃字节、最近错误。
8. 用同一黄金字节流按单字节、随机分块、大块输入分别验证 Rust/Web 结果一致。

完成标准：非法 UTF-8 和任意二进制不会先经文本解码破坏；配置选择真实影响实时输出。

### T04：统一发送、结果与软件停止（F06、F07、F08）

1. 建立共享 `encodeCommand()`：显式文本/HEX；严格校验 HEX；文本转义与无/LF/CR/CRLF 选项明确。
2. 终端、快捷命令、控件、周期发送和调参只产生统一 `WriteRequest` 并经过同一网关。
3. Rust 写线程回传驱动 `write_all/flush` 结果；失败传回调用方并留痕，不记成功 TX。
4. RX/TX 字节计数只用实际读取/写入回执，分别统计请求数、写入字节与解析样本数。
5. 发送失败保留用户输入；历史保存原输入及最终字节预览。
6. 软件停止先阻止新普通写入，再取消前端/后端队列、周期发送和调参，之后仅发送用户配置的停止字节。
7. 屏障保持锁定，重连和工程导入不解锁；必须用户明确恢复。
8. 对已经进入驱动的请求标为在途；只对“能力不存在”做兼容，真实 I/O 错误不重发。

完成标准：屏障后没有新普通写入；排队、驱动完成、设备 ACK、失败、取消、替代均可区分。硬件停机效果必须另验。

### T05：分段记录、恢复、回放与导出（F04、F05、F15）

1. 每次会话使用独立目录：`manifest.json`、分段 `rx-*.bin`、`chunks.jsonl`、`events.jsonl`；段默认 64 MiB。
2. 记录队列有界；过载/磁盘失败中断记录并提示缺口，采集可继续但标明“记录已中断”。
3. manifest 原子替换；启动时扫描未正常结束记录，恢复最后完整前缀并标注异常结束。
4. 不因会话数量删除旧记录；容量策略在用户确认后执行。
5. 提供记录列表、备注、协议、时长、字节数、完整性状态与只读回放定位/倍速。
6. 回放只驱动显示和分析，绝不连接写入链路。
7. CSV 从所选记录区间的原始解析样本导出，不用显示降采样；旧 CSV 可读但标明无法恢复既有损失。
8. 清屏、清显示缓冲和删除磁盘记录使用不同动作。
9. Web 记录使用 IndexedDB 与容量上限，支持导出并报告写入错误。

完成标准：回存 RX 与输入逐字节一致；异常退出恢复有效前缀；磁盘不足可见；回放没有物理写入。

### T06：波形时间轴、显示状态与有界性能（F09、F10）

1. 每通道保存会话、样本时间、序号、质量；名称、单位、颜色、倍率和偏置作为稳定 ID 的元数据。
2. 按真实时间戳并集排列多通道；缺失点留空，不按索引拼接、不插值伪造测量。
3. 明确实时跟随、暂停显示、历史浏览三态；拖放/缩放保持窗口，显式“回到实时”恢复跟随。
4. 全局暂停和局部暂停只控制绘图；采集和记录继续。
5. 用时间窗裁剪；可见区采用保留峰值的降采样；不复制全部历史到每帧。
6. 缓冲容量可作用于既有通道，缩小时保留最新样本并显示丢弃区间。
7. 默认最多 64 个活动通道、每通道最多 50,000 点，并设总内存上限和过载提示。
8. 修复通道重命名、隐藏、颜色、图例和 CSV 的稳定 ID 映射。
9. 非活动 Tab 停止绘制；控件卸载释放计时器、观察器和指针监听。

完成标准：错频/缺样不错位；缩放和暂停稳定；CSV 不依赖显示抽样。峰值性能需以目标机器测量。

### T07：分析前提与质量门禁（F11）

1. 每个分析要求用户明确通道、区间、单位和时间来源。
2. 校验时间单调、重复/缺失点、非有限值、样本量和采样间隔。
3. FFT 对非均匀时基默认拒绝；重采样只能由用户显式选择，结果标为估计。
4. 阶跃分析要求明确参考量或标定阶跃时间与幅度，不假设幅度为 1。
5. 系统辨识要求用户标记开环/闭环输入输出与区间；删除默认第一通道回退。
6. 相位裕度只由适用模型、控制器和频域交越计算，结果标“模型预测”；缺交越返回未知。
7. 重分析和仿真在 Worker 执行，提供取消、超时和样本预算。
8. 用独立解析解/参考数据测试；SIL 固定随机种子并标为软件一致性验证。
9. 结果附来源会话、区间、算法和参数，以便重算。

完成标准：前提不足时可读地拒绝；同一记录重算结果一致；SIL 不冒充实测。

### T08：工作区、迁移与密钥边界（F14、F15）

1. 单一版本化工作区覆盖连接、协议、命令、通道元数据、布局、控件、控制结构和记录索引。
2. 导入检查版本、Schema、有限数值、容量、ID 唯一性、引用及协议支持。
3. 导入先预览差异，确认后整体替换；失败不留下部分应用状态。
4. 命令以草稿导入，不带周期任务、停止槽绑定和自动调参权限。
5. 配置原子保存并展示保存中/已保存/失败；解析失败保留旧文件，不用默认值静默覆盖。
6. API Key 从普通配置和工程模型移除；Windows 通过 DPAPI 保存，AI 请求由后端携带密钥发出。
7. 旧明文迁移须先加密、回读校验，再清除明文；失败保留原文件并显示错误。
8. Web Key 只在当前会话内保存；日志、错误页和导出脱敏。
9. 设置适当 CSP 与最小 IPC 权限，验证 Worker、资源和 AI 请求。

完成标准：工程导入导出保持配置一致且无密钥；迁移错误不损坏旧工作区；持久化、日志和导出中无明文。

### T09：首次使用与日常交互（F16）

1. 首次进入提供“连接设备”“体验演示”“打开记录”三个入口。
2. 演示使用独立数据源，持续标明演示；提供正弦、阶跃、异常样本且不能触达设备写入。
3. 分别解释未连接、已连接无字节、字节到达但解析失败、数据未绑定、正常显示。
4. 默认锁定画布；编辑时禁止控件发送。属性面板统一绑定、单位、范围、颜色、模板和启用状态。
5. 滑块默认松手发送；连续发送需用户开启并受节流。输入框默认 Enter/应用后发送。
6. 控件分开显示待确认、本地目标值、设备回读和超时。
7. 移除默认假定固件支持的命令；删除控件/重置布局提供恢复路径。
8. 统一产品名和版本来源，检查键盘、焦点、快捷键和非颜色状态提示。
9. 在 960×600、1280×800、1920×1080 和 125%/150% 缩放验收，窄窗次要操作移入菜单。

完成标准：新用户可进入独立演示；接入失败有下一步；每个保留控件有真实结果与错误态。

### T10：AI 建议和安全调参（F12、F13、F14）

前置依赖：T02–T08。

1. 合并 Copilot、日志诊断和候选生成客户端；支持兼容服务、本机无 Key 服务、取消、超时和限流。
2. 请求前展示摘要范围；默认不上传完整日志、原始波形或密钥；会话/配置改变时丢弃迟到响应。
3. AI 返回结构化候选、依据和不确定性；本地 Schema、范围、变化率和拓扑约束重新验证。
4. 把调参状态机从 Vue 展示组件提取为服务：草稿→候选→待写入→等待确认→采集→评价→暂停/失败/完成。
5. 候选绑定设备、会话、配置版本、参数基线和证据；任一变化需重新验证。
6. 手动与自动试验持有写入租约；普通控件/周期任务不得抢写；软件停止始终可用。
7. 新鲜度基于该通道新样本；ACK 必须与本轮请求、写入后时间和配置版本关联。
8. 固件没有相关 ACK 时提供人工核对模式，不用泛化 `OK` 自动推进。
9. 评价窗口从确认写入后开始；断线、数据过期、配置变更、越界都暂停。
10. 立即持久化每次状态变更；恢复能力通过正常写入和确认，不将“已发出”显示成“已恢复”。
11. 有界自动调参默认关闭；只有专门安全验收后才开放轮数、总时限、边界和停止条件。

完成标准：迟到 ACK/回读、断线、配置变化和停止不会推进错误试验；AI 无法越过本地写入权限。

### T11：结构、自动化与发布（F17）

1. 将连接、发送、记录、工作区、分析和调参拆成职责清晰服务；主组件只负责组合和事件连接。
2. 以可替换接口隔离时钟、串口、文件存储与 AI 客户端，支持确定性测试。
3. 依赖分析后逐个删旧组件；只清理已确认无入口且无用户数据依赖的代码。
4. 统一错误分类与处理，逐步收紧 `any`。
5. 增加组件/端到端测试，验证用户动作结果；不以源码字符串搜索充当验收。
6. 调参、Copilot、重分析按需加载；维持离线基础串口能力。
7. 版本号从单一来源读取；去除重复构建；复制/压缩任一步失败都令发布失败。
8. 每次生成独立发布目录和清单：版本、源码状态、锁文件哈希、构建时间、EXE 哈希及测试结果。
9. 发布包不带用户 `data`、密钥或真实记录；升级保留数据。
10. 在隔离数据目录验证最终 EXE 启动、关闭、二次启动、配置恢复与 WebView2 依赖。
11. 更新用户手册、固件接入、故障排查，并按实际证据标记功能状态。
12. 未有签名流程的包标为未签名测试发行。

完成标准：源码快照可生成可核对发布包；发布成功表示所有必需步骤成功；文档、界面、版本和代码一致。

## 验收矩阵

| 类别 | 核心输入/故障 | 验收结果 |
|---|---|---|
| 连接 | 占用、无设备、拔插、快速重连、100 次循环 | 状态真实；无重复订阅、旧会话数据或悬挂句柄。 |
| 配置 | 7/8 位、校验、停止位、流控、信号 | 驱动实际参数正确；不支持项明确拒绝。 |
| 协议 | 单字节/随机分块、粘包/残包、坏校验、长帧、非法 UTF-8 | Rust/Web 黄金样本一致；记录字节不变；错误可定位。 |
| 写入/停止 | 文本、HEX、转义、换行、队列满、I/O 失败、周期发送 | 精确字节可核对；屏障后无新普通发送；在途写明确披露。 |
| 波形 | 不同频率、缺样、清会话、重命名、缩放、暂停 | 按时戳对齐；缺口可见；会话不混；CSV 不降采样。 |
| 记录/回放 | 长录、磁盘满、异常退出、恢复、导出 | 逐字节核对；过载非静默；可恢复有效前缀；回放无写入。 |
| 工程 | 旧格式、损坏、非法数值、断电、导入导出 | 原文件可恢复；没有半导入；不携带授权/密钥。 |
| 分析 | 正弦、阶跃、抖动、缺失、无交越、发散仿真 | 有效样本误差达标；前提不符拒绝或未知。 |
| 调参 | 旧 ACK、旧回读、断线、配置改变、停止、回退失败 | 陈旧证据不推进状态；每次转换可审计。 |
| AI | 超时、取消、畸形响应、本机服务、迟到响应 | 界面不冻结；不越权发送；持久化无 Key。 |
| UI/发布 | 首次启动、小窗/高 DPI、隔离目录、更新 | 关键操作可达；错误有下一步；EXE 与清单一致、数据保留。 |

性能测试生成 8 通道×1 kHz 连续 30 分钟与 20 通道×1 kHz 连续 5 分钟样本。目标机器记录配置后，基础工况下主要交互 p95 <100 ms、波形约 30 FPS、内存有界；超出能力须提示过载，不能宣称完整采集。生成器性能不代表 USB 实物串口性能。

硬件先用回环/专用固件验证收发字节、拔插和停止顺序；执行机构测试必须另行确认固件命令、参数边界及独立安全链。没有设备时只标记“软件集成通过，硬件验收待完成”。
