## 一、改造核心目标与架构对比

### 1.1 原架构 vs 新架构形态对比

| 模块维度 | 原架构（ADR 0001 / ADR 0007） | 新架构（ADR 0008 VOFA+ 范式） |
|---|---|---|
| **顶层入口** | 顶部 Tab 切换（纯终端、终端+波形、终端+控件仪表） | **单一工作台主入口**，彻底取消三模式切换 |
| **主工作区** | 55% 终端 + 45% 扩展视区固定左右分屏 | **100% 全屏多 Tab 自由画布** |
| **波形呈现** | 独立的波形大页面组件，挤在右侧小分屏中 | **画布内旗舰级 ChartWidget**，默认 Tab 1 全屏铺满 |
| **左侧操作区**| 无，分散在顶部或模态框中 | **40px 垂直 Icon Dock**（连接、协议、控件库、工程） |
| **控件库调取**| 仅在模式三左侧显示一个窄条面板 | 点击 Dock 图标向右滑出**悬浮控件抽屉**，直接拖拽入网格 |
| **终端交互** | 55% 常驻占据大半个屏幕，大量空白浪费 | **底部紧凑双行控制条**（采样流控 + 单行发送）+ 按需上滑展开的日志抽屉 |
| **Copilot 集成**| 作为右侧第三 Tab 或零散卡片 | **底部抽屉**（收起为状态条/事件胶囊，展开为完整对话/Bode分析） |

## 三、关键风险防范与安全边界

1. **图表性能与多 Tab 资源保护**：
   - 必须坚持非激活 Tab 暂停 Canvas 绘制的策略，数据仍在全局 `ChannelStore` 缓冲，切换 Tab 瞬间重新 `setData`，避免后台 Tab 浪费 GPU/CPU。
2. **终端收折时的防误触**：
   - 底部单行发送框与快捷指令即使在日志抽屉收起态下也始终可用，保证随时下发调参命令，不增加操作步骤。
3. **安全急停通道第一性**：
   - 空格键触发的全局急停（ADR 0004）不受当前处于哪个 Tab 或抽屉是否展开的影响，全局最高优先级拦截。
