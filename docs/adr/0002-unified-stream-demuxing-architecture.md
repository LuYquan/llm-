# ADR 0002: 单物理流智能分流架构（波形数值流与文本日志流）

- **状态 (Status)**: 已接受 (Accepted)
- **日期 (Date)**: 2026-09-22
- **决策人 (Deciders)**: 架构师团队

---

## 1. 背景与问题陈述 (Context)

在嵌入式开发调试中，单片机往往只有 1 个调试串口（UART），工程师不仅通过该串口输出时序波形数据（如 `10.0,8.5,30.2\n`），还会混合输出系统调试文本（如 `[INFO] Sensor Init OK\n`、`[WARN] Voltage Low\n`）。

若由前端 JavaScript 处理分流，高频串口数据（例如 100Hz~1kHz）会导致大量无效的 IPC 序列化开销和正则表达式 CPU 占满；若要求单片机开双串口，则极大增加了硬件连线和嵌入式工程师的负担，违背“单片机一行 printf 极简接入”的设计初衷。

---

## 2. 备选方案权衡 (Alternatives & Trade-offs)

### 方案 A：双物理串口隔离（一个波形串口，一个日志串口）
- **优点**：硬件层完全隔离，互不干扰。
- **缺点**：绝大多数开发板（如 STM32F1/ESP32）只有一组 USB 转串口引出；占用两个 COM 端口，用户操作繁琐。

### 方案 B：前端 JavaScript 正则过滤
- **优点**：Rust 端实现最简单，只做纯管道搬运。
- **缺点**：每一行原始文本都要跨 IPC 推给 Webview，在 1kHz 采样率下会导致 Webview 垃圾回收频繁，引起波形掉帧与高延迟。

### 方案 C（选定）：Rust 端统一管道 + 零拷贝智能分流（StreamDemuxer）
- **优点**：
  - 单片机依然只需要单串口、无侵入 `printf`；
  - Rust 底层逐行扫描：
    - 若整行符合数字浮点规则（逗号分隔或 Teleplot），直接写入【时序环形缓冲池】并触发 LTTB 降采样；
    - 若包含非数字文本字符或以 `[`/`#`/`*` 等日志前缀开头，自动提取写入【日志环形缓冲池（LogRingBuffer）】；
  - 文本日志以 10Hz 节流批量推送给前端日志抽屉，波形以 60Hz 批次推送给 uPlot，两者性能极致隔离。
- **代价**：Rust 端行解析器需增加一套快速轻量的字符判断状态机。

---

## 3. 决策内容 (Decision)

1. 在 Rust 核心层实现 `StreamDemuxer`，作为物理 `DataSource` 与具体数据处理组件之间的中间件。
2. 建立双缓冲机制：`TimeSeriesRingBuffer`（专供波形，百万点级）与 `LogRingBuffer`（专供文本日志，2000行）。
3. 文本日志视图默认收纳在底部抽屉，用户可随时展开查看时间戳标记的原始报文。

---

## 4. 影响与后续结果 (Consequences)

- 保证了单片机接入的极简体验（一行 printf 即可混合输出日志与波形）。
- 杜绝了非数值文本导致的波形解析异常，同时避免了高频文本对前端 DOM 的冲击。
