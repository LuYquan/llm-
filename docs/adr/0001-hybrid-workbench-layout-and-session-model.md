# ADR 0001: 采用融合工作台布局（波形+AI+日志抽屉）与多会话连接管理模型

- **状态 (Status)**: 已接受 (Accepted)
- **日期 (Date)**: 2026-09-22
- **决策人 (Deciders)**: 架构师团队、产品设计团队

---

## 1. 背景与问题陈述 (Context)

在传统嵌入式调参和串口调试中，工程师通常面临两种极端工具形态：
1. **纯文本串口助手（如 SSCOM、XCOM、electerm）**：擅长查看文本日志、十六进制收发和快捷指令，但完全缺乏高频时序波形可视化与控制指标分析能力。
2. **纯波形遥测工具（如 VOFA+、Serial-Studio）**：专注于多通道波形绘制，但通常将非数值格式的普通文本日志过滤或视为错误，导致工程师无法看到单片机输出的 `[ERROR] Sensor timeout` 等排错信息。

本项目旨在打造面向嵌入式与机器人的新一代“大模型 PID 调参工作台”，核心体验既需要高频 60FPS 实时波形与 AI 闭环，又不能剥夺工程师查看原始文本日志和发送基础指令的底层刚需。

---

## 2. 备选方案权衡 (Alternatives & Trade-offs)

### 方案 A：纯净专注方案（仅保留波形 + AI 调参）
- **优点**：极致轻量，UI 最精炼，无任何冗余组件。
- **缺点**：割裂严重。单片机如果有调试文本输出将无法查看，工程师必须同时开两个串口工具（由于串口独占性，甚至会导致端口冲突不可用）。

### 方案 B：全能多标签方案（类似 electerm，分 Tab 1 终端 / Tab 2 波形）
- **优点**：每个功能视图独立，显示区域最大化。
- **缺点**：切换成本高，调参时无法同时观察波形与下位机状态日志。

### 方案 C（选定）：融合方案（双栏主布局 + 底部可折叠日志抽屉 + 顶栏会话管理）
- **优点**：
  - 核心 80% 视野给予【实时波形视窗】与【AI 调参卡片】；
  - 底部提供【可折叠/抽屉式原始日志栏与快捷指令】，默认可收起，展开时即时显示文本日志与发送指令；
  - 顶栏引入 electerm 式的【会话与配置持久化】，支持多设备配置保存与一键重连。
- **代价**：前端布局状态管理略微增加，需要协议解析层区分“数值波形行”与“普通文本日志行”。

---

## 3. 决策内容 (Decision)

1. **界面布局**：采用【顶栏会话管理】+【左区 70% 实时波形】+【右区 30% AI 调参控制】+【底栏可折叠原始日志/快捷指令抽屉】的整体架构。
2. **协议分流**：协议嗅探器（ProtocolSniffer）若识别到非数值且非协议帧的文本行，自动将其作为普通日志派发至底栏日志视图，保证单片机 `printf` 日志不丢。
3. **会话持久化**：引入 `SessionManager`，支持用户将当前波特率、通道名称、PID 参数上下限与 Prompt 预设保存为命名的设备会话。

---

## 4. 影响与后续结果 (Consequences)

- **正面影响**：
  - 彻底解决串口工具“独占冲突”痛点，用户无需在波形工具和串口助手中来回切换。
  - 用户体验大幅跃升至专业工程级（借鉴了 electerm 的连接管理与 SerialTest 的调试实用性）。
- **负面影响 / 应对**：
  - 前端渲染需处理文本日志与 Canvas 波形并存的渲染负荷。日志视图必须采用虚拟滚动（Virtual Scroll）限制最大行数，防止大吞吐下 DOM 膨胀。
