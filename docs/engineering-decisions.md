# LLM串口 — 工程技术决策与算法基准 (Engineering Decisions)

> 本文档用于冻结 MVP 开发过程中所有算法阈值、时间窗口及实现细节，避免开发期反复摇摆。

---

## 1. 算法基准与阈值冻结

| 参数项 | 冻结数值 / 规则 | 理由与工程依据 |
|:---|:---|:---|
| **上升时间 ($t_r$)** | 响应由阶跃幅值 $10\% \to 90\%$ 所需时间 | 控制工程国际通用标准定义 |
| **超调量 ($M_p$)** | $M_p = \frac{y_{max} - y_{ss}}{y_{ss} - y_0} \times 100\%$ | 稳态值 $y_{ss}$ 取阶跃稳定后最后 $10\%$ 点的均值 |
| **调节时间 ($t_s$)** | 进入目标值 $\pm 2\%$ 误差带，并持续维持 $\ge 500ms$ 的时刻 | 避免因单次穿越误差带导致的误判 |
| **稳态误差 ($e_{ss}$)** | $e_{ss} = \|y_{target} - y_{ss}\|$ | 衡量控制精度 |
| **阶跃前置窗口 (Pre-Window)** | 阶跃发生时刻前 $500ms$ | 用于记录阶跃前的初始稳态基线 $y_0$ |
| **阶跃后置窗口 (Post-Window)** | 最大 $10s$，或判定进入稳态后额外记录 $1s$ | 保证抓取完整动态过程，且防止切片无限延长 |
| **降采样触发阈值 (LTTB)** | 当时序数据点数 $> \text{视窗像素宽度} \times 2$ 时启用 | 保证 60FPS 渲染性能，同时完整保留极值波峰波谷 |

## 2. 协议与数据流细节决策

### 2.1 Teleplot 时间对齐策略
Teleplot 协议按行传输（如 `>sp:10\n>act:9.2\n>out:30\n`），不同变量分属不同行。
- **决策**：Rust 解析器内部维护 `HashMap<String, f64>`（最近值缓存）。
- **策略**：当收到新的一轮变量或达到特定微秒时间窗口阈值（如 $1ms$）时，将当前缓存的全部变量打包为一个对齐的 `SamplePoint`，严禁将每一行单独当作一个时间点，彻底杜绝时间轴错位。

### 2.2 环形缓冲容量约束
- `TimeSeriesRingBuffer`：固定存储最近 $60$ 秒原始数据（按 1kHz 计算约为 60,000 点），禁止动态无上限扩容。
- `LogRingBuffer`：固定容量 $2000$ 行，满载后自动淘汰最旧日志行。

### 2.3 IPC 批量派发频率
- 波形数据（Rust → Vue）：严格限制在 **60Hz** 批量 emit（`waveform://batch`）。
- 文本日志（Rust → Vue）：严格限制在 **10Hz** 批量 emit（`logs://batch`）。

## 3. 安全防线 (SafetyGuard) 规则

1. **非法数值硬拦截**：检测到 `NaN`、`Infinity` 直接拦截，报错提示。
2. **符号反转硬拦截**：$K_p, K_i, K_d$ 发生正负号颠倒（如正变负，可能导致正反馈发散）直接拦截。
3. **幅值保护**：第一版预留上限配置项，默认不设全局硬限制，允许用户自定义。
4. **急停行为状态机**：
   - 输入框处于聚焦输入状态：不触发急停；
   - 未配置急停指令：弹出引导提示，不发送字节；
   - 串口未连接：提示未连接；
   - 已连接且已配置：按下空格键即刻向串口发出急停字节流。

## 4. 品质雷达图评分归一化 (`MetricScorer`)

集中在 Rust 端实现统一评分算法，前端仅接收 0~100 分：
- **超调得分**：$M_p \le 5\% \to 100$ 分；$M_p \ge 50\% \to 0$ 分（线性衰减）。
- **速度得分**：根据上升时间 $t_r$ 相对于设定基准评估。
- **稳态得分**：根据稳态误差 $e_{ss}$ 评估，误差接近 0 趋近 100 分。
- **阻尼得分**：根据震荡衰减比与极值点衰减速率评估。
- **鲁棒得分**：结合扰动恢复与输出控制量平滑度综合评估。
