# ACK 原始接收顺序与验收

场景调参仍在串口主工作区中执行。用户核对候选和最终字节，驱动完成写入后，系统才等待设备确认。唯一轮次 ID 防止上一轮应答串入，但同 ID 的发送前应答不能仅凭界面派发时间被认定为新应答。

## 本轮修复

Web Serial 在 `read()` 返回非空块后、通知原始字节监听器前分配接收序号。原生读取线程在实际 `Read::read` 边界保存块的会话、协议代次、序号和相对时间；管线消费积压数据时不得重新贴身份。序号在一次连接中递增，切换协议不归零。

FireWater 文本行保留 `rx_origin`：`source`、`session_id`、`epoch`、`first_rx_sequence` 和 `last_rx_sequence`。跨分块行使用首个贡献分块的序号；协议重置丢弃残行，未知来源不升级为可信证据。超长行超过 64 KiB 后，连同其未换行的后续尾部一起丢弃，避免尾部被解释为新的 ACK。

正常写入在真正调用 `writer.write()` / 首次 `Write::write` 时截取 `rx_dispatch`，包含来源、会话、代次和此前接收水位。排队回执没有这项证据。完成和失败结果保留实际派发身份，异步完成不使用当前连接重新命名原写入。

自动 ACK 确认同时要求：本轮精确协议 ID、完整 RX 成功行、驱动 written、写入与当前会话及代次一致、来源一致，以及 `first_rx_sequence > rx_dispatch.rx_sequence`。缺失或非法来源字段按未确认处理。界面日志 ID 和显示时间只是附加过滤，不是原始字节因果证明。合法 ACK 可以早于 written 回执到达，待独立写入完成后再确认。

## 原生时序取舍

Rust 以共同互斥边界覆盖一次正在执行的读取及首次写入调用，写入等待者阻止新的读取抢先。读取沿用现有 50 ms 超时，因此写入可能多等待一个正在执行的读取周期；后续部分写入与 flush 不持有该锁，允许设备应答在写入完成事件前被读取。软件停止仍清理待发队列并优先排入停止字节，不能撤回已经进入驱动的写入。真实驱动延迟、停止时延和持续吞吐仍需硬件测量。

已读的旧代次原始块保持原标签，解析器拒绝将其升级到新代次。每份记录以开始时的会话和代次为边界；不匹配的积压块不进入当前记录，排除的块数与字节数同时保存在状态和清单，并在终端及记录库中显示。这样不会把旧块重贴成新块，也不会写出单代次索引无法回放的混合记录。

## 可执行软件验收

运行 `npm run test:transport`、`npm run test:tuning` 和 `cargo test --locked --manifest-path src-tauri/Cargo.toml --no-fail-fast`，随后启动独立夹具：

```powershell
node tests/browser/ack-causality-harness.vite.mjs
```

打开 `http://127.0.0.1:5198/tests/browser/ack-causality-harness.html`。夹具使用实际 App、session、WebSerialTransport 和 module Worker；仅用合成 ReadableStream/WritableStream 端口与本地确定性 HTTP 响应。先连接、配置夹具密钥、确认 PI 基线，再生成本轮候选并打开最终发送审批。夹具控件读取可见命令中的 UUID，不修改 Vue 状态，也不替用户批准发送。

| 分支 | 操作与预期 |
| --- | --- |
| 完整旧 ACK 延迟派发 | 在最终审批内输入完整 ACK，等真实 Worker 显示已解析并缓存；批准实际写入后放行缓存。应超时停止，无确认、评价或下一轮。 |
| 旧 ACK 前缀跨写入补完 | 在审批内输入无换行前缀并立即批准；实际写入时夹具输入后缀。应按首块序号拒绝，无评价。 |
| 写后 ACK 早于 written | 不输入旧 ACK，正常批准。写入后 30 ms 输入精准 ACK，written 延迟 1 秒；完成前不得确认，完成后允许评价。 |

各分支重载创建独立会话，使用“记录实际 App 证据”保存真实日志字段、回执、写入字节、持久化轮次与可见状态。修复前已发布源码的独立快照复现了完整旧 ACK 延迟派发后仍完成评价；其事件顺序单独保留，不计为通过案例。

## 证据范围与仍待验收

这些序号证明主机读取 API 与写入 API 的顺序。操作系统或 UART 中已经缓存、但主机尚未读取的旧字节，仍可能在写入后才返回；本设计不能证明物理到达时间或设备执行。固件必须精确回显本轮 token，并在参数真正应用后应答。仅凭 ACK 本身仍不能证明设备稳定、参数公式正确或安全停机。

浏览器合成验收与 Rust 行为测试不等于原生窗口交互、真实 Tauri queued/result IPC、真实串口、拔插、在线 AI 或硬件 PID 闭环验收。硬件验收还须记录版本、端口、固件、实际命令、应用后应答、停止与恢复、部分写入及长时间采集。异步写入权重新获取、其他视口、签名、许可证和 Rust 公告 strict 门槛继续单独列项；本轮没有调用 Jev。
