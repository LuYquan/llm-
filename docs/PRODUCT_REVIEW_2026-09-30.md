# 产品体验审查与迭代方案（2026-09-30）

本轮依据当前源码、浏览器实际操作和 GitHub 官方仓库。评估采用嵌入式调试与软件维护的工程标准；不声称作者拥有某个真实从业年限，也不把浏览器测试当作原生程序或硬件验收。

## 结论与产品定位

当前产品的主要问题是复杂度出现得过早、默认语义过于偏向电机/PID，以及 AI 与用户日常任务脱节。功能多本身不是问题；打开软件就要求理解画布、三环拓扑、相位裕度和模型配置，会使初学者难以完成第一条收发，也使专业用户频繁绕路。仅统一颜色不足以解决这些问题。

目标是“可靠的串口与波形工作台 + 任务型调试助手”。用户已确认 AI 应结合选中日志/波形理解问题，生成配置、控件或命令预览，确认后应用。默认终端与波形共用、控件按需添加、AI 默认收起、高级控制分析按需打开，是本轮可逆实现采用的组织方式；另一个布局偏好问题尚未收到答复，可后续调整。

## 用户任务与界面问题

| 用户 | 最常见任务 | 原界面障碍 | 目标流程 |
|---|---|---|---|
| 初学者/学生 | 连接板卡，发送已知命令，看到响应 | 默认控制术语、空绑定、收发区域过小、AI 要先理解环路 | 选择端口→连接→终端看到字节/日志；需要波形时选协议；失败时有下一步 |
| 固件工程师 | 核对帧、校验、时序、重复命令与记录 | 工具分散，编码状态可能丢失，显示与原始数据混称 | 终端/波形同步观察→有界记录→按区间分析；发送失败保留输入 |
| 控制工程师 | 建模、仿真、参数试验 | 示例数据与实测证据混淆，默认高级入口过多 | 主工作台获得可信数据→高级工具声明实验语义与绑定→复核模型→受限试验 |
| 社区贡献者 | 增加解析器/控件、分享工作区 | 缺少最小贡献路径、测试样本和兼容说明 | 按数据契约扩展→黄金样本与交互验证→明确兼容和证据等级 |

## 本轮已经实现的工作方式

1. 主工作台先连接、收发、观察。新默认波形只绑定真正有样本的前 8 个通道，不预设设备语义；全会话通道不会因稀疏批次只更新一个通道而从助手列表消失。
2. AI 入口集中为任务助手；点击日志的“选择给 AI”只预填选中证据。最近 5 条日志和通道摘要默认不选，不直接发送。
3. 每个选择通道最多取最近 256 个显示缓冲点，上传统计摘要而非原始数组。精确 FFT、阶跃等仍使用本地分析入口。发送前可查看摘要，结果保留本轮发送依据、模型和时间。
4. 云 Key 通过桌面受保护保存；网页仅当前会话使用。更换服务/地址要求重新填写相应凭据，本机兼容服务可无 Key。读取模型先等保存结果，再读取，错误明确反馈。
5. 命令草稿必须显式 text/hex、转义、换行；预览最终字节。确认只填输入，不发送。普通语言和未知动作不取得写入能力。
6. 显示控件只允许 chart/number、当前已知通道、容量约束；协议建议只接受有效 FireWater/JustFloat/RawData。CustomFrame 的完整结构继续在连接面板核对。
7. 请求可取消；连接、协议代次、数据代次、服务或模型变化会使结果失效。软件停止与调参授权继续由本地通信服务决定。
8. 模型/仿真从高级工具进入；仿真只绘制模型预测，没有合格实测证据时表格显示“—”。PID 代码示例默认折叠，并明确示例限幅和固件核对要求。Worker 将响应式选项转换为独立参数快照，不改写 NaN/Infinity，并保留本轮参数作为溯源。
9. 默认单波形视图随窗口变化适应宽度；用户开始布局编辑后保留其几何设置。Escape 只关闭当前上层面板，不同时收起后台终端。条形显示直接更新宽度，不用动画延迟实时数据。
10. 显式清除已保存 Key 可以独立保存，需要 Key 的服务随后返回缺少凭据状态；不会用“必须有 Key”校验阻止删除。

## 后续实施顺序与验收

### P-A：统一剩余界面与控件（当前迭代之后）

1. 按 DESIGN.md 扫描控件属性、连接协议、记录库、Bode 和参数实验，记录截图与字体/间距差异；一次处理一个完整用户任务，不只改 CSS。
2. 属性面板按照“绑定→单位/范围→外观→发送（仅控制控件）”组织。显示控件不展示发送权限；控制控件必须先绑定协议模板再启用。
3. 滑块默认松手提交，数值框 Enter/应用提交。连续发送单独启用并节流。本地期望、排队、已写入、已回读/超时分别显示。
4. 快速波形加明确的自动绑定开关；手动选择通道即退出自动绑定。最多 8 曲线之外给出提示，不默默隐藏所有新增通道。
5. 终端保留真实原始字节来源，文本 HEX 标签明确是显示文本的编码。增加选中区间、日志序号和来源，避免把格式化日志当原始 RX。
6. 增加布局撤销/重做：变更前保存当前工作区快照；导入整体提交；删除、重置、模板添加可以撤销。刷新恢复有版本校验。
7. 验收：连接/发送/停止在 960×600 与高 DPI 可达；Tab/Enter/Esc 可完成关键路径；图表暂停不停止记录；编辑布局不执行控件命令。

### P-B：把助手发展成可复盘的调试任务

1. 用显式 EvidenceSelection 保存会话、日志序号、通道、区间、时间来源和截断信息。日志选区不再只能粘贴文本。
2. 本地分析生成可信指标后再作为 AI 证据提供；助手可提出“运行分析”预览，执行由本地分析服务完成。不能用显示摘要伪算频率/相位裕度。
3. 增加结构化诊断假设、证据、验证步骤、所需信息和置信限制。用户可逐项标记已验证；无依据时询问接线/协议，而非编造硬件结论。
4. 记录请求/取消/响应/建议校验/应用事件，密钥不进入历史；离线再次打开能知道建议基于哪一段数据。
5. 为提案添加差异、撤销和可编辑草稿；协议更改影响窗口和残留应明确显示。命令草稿的字节规则不随另一页面改变。
6. 验收真实在线模型：官方/兼容/本机分别测试成功、超时、限流、畸形 JSON、地址切换与迟到结果；不自动替换服务或重发物理命令。
7. 当前本机固定响应只证明 UI 和网关集成，不证明模型诊断质量。建立匿名合成任务集：乱码、校验、粘包、无数据、波形绑定、采样时钟不明；给正确拒绝与下一步评分。

### P-C：社区扩展与交付

1. 先公开源码结构、构建入口、协议黄金样本、工作区格式和显示控件注册接口；每个扩展附版本、示例和兼容范围。
2. 增加最小显示控件/协议解析器贡献示例。插件先通过接口评审、确定性样本和卸载资源检查，再考虑运行时装载。
3. 模板仅是配置，不带 Key、自动发送、设备确认或执行权限。未知字段按版本报错，不伪装成已支持能力。
4. 已建立 `.github/workflows/checks.yml`：锁定依赖安装、前端测试、Rust、协议黄金样本和生产构建。本轮仅验证对应本地命令，尚未在 GitHub Runner 执行；Windows 发布另跑最终 EXE 检查。
5. 所有者确认许可证与第三方字体、头像、图标、依赖、固件示例的权属；生成依赖/许可清单。没有确认前不加任意许可证、不代为公开发布。
6. 发布说明写已验证功能、已知限制、迁移/恢复方式与支持平台。签名未建立时标记未签名测试发行。

### P-D：成熟度门槛（不能用主观反复打磨代替）

- 新用户：无指导完成“演示→真实连接→首条发送→波形→记录回放”；每处失败能理解下一步。至少 3 类用户反馈，并记录任务耗时/失败原因。
- 通信：回环/测试固件逐字节收发；拔插、占用、100 次重连、停止屏障；真实驱动设置核对。
- 数据：二进制记录一致、异常退出恢复、磁盘满反馈、不同采样率正确对齐、导出不受降采样影响。
- 性能：记录测试机；8×1 kHz 30 分钟与20×1 kHz 5 分钟；交互 p95<100 ms、目标约30 FPS、内存有界、记录缺口显式可见。
- AI：合成任务质量评测与真实服务集成各留证；无越权、无旧建议应用、无持久化明文密钥。
- 发行：可追溯源码摘要、EXE/ZIP 哈希、独立数据目录原生启动/关闭/恢复、WebView2 表现与升级保留数据。
- 开源：许可证/资产权属确认、贡献路径可执行、维护者能处理问题和兼容迁移。

这些门槛未全部完成之前，产品阶段是可审阅的 Beta 迭代，不标记正式成熟发行。
