## 详细故障排查

### F01 串口下拉列表为空或找不到设备

- **现象描述**：插入 USB 转串口模块后，顶部串口下拉框中无新端口，点击刷新按钮（↻）仍为空。
- **可能原因**：
  1. 操作系统缺少对应 USB 转串口芯片的驱动程序（如 CH340/CH341、CP2102/CP2104、FT232、PL2303 等）；
  2. 采用仅有供电功能的两芯 Micro-USB/Type-C 线（无 D+/D- 数据线）；
  3. 串口被虚拟机（如 VMware、VirtualBox、WSL）自动抢占挂载。
- **排查与解决步骤**：
  1. **检查设备管理器**：右键 Windows“开始”菜单 $\to$【设备管理器】$\to$ 展开【端口 (COM 和 LPT)】，观察是否有黄色感叹号或未识别设备；
  2. **安装对应驱动**：若存在感叹号，前往官方渠道安装 CH340 或 CP210x 驱动；
  3. **更换线缆与接口**：更换确认带数据传输功能的线缆，并插至机箱后置原生 USB 接口测试；
  4. **释放虚拟机占用**：若开有虚拟机，在虚拟机设置的“可移动设备”中将该 USB 串口设备断开并连接至主机。

### F02 打开串口报错提示“设备被占用”

- **现象描述**：选择 COM 口后点击【打开串口】，弹出红色告警或提示 `Access Denied` / `Port Busy`。
- **可能原因**：
  1. 其他调试工具（如 XCOM、SSCOM、VOFA+、Keil/IAR 仿真器监视器、串口终端）正在占用该端口；
  2. 软件此前非正常退出，后台存在残留的旧进程句柄未完全释放；
  3. 某些打印机驱动或蓝牙服务在后台轮询该虚拟串口。
- **排查与解决步骤**：
  1. **关闭第三方软件**：检查任务栏与托盘，彻底关闭其他所有串口助手及嵌入式 IDE 的串口监视器；
  2. **检查进程管理器**：按 `Ctrl + Shift + Esc` 打开任务管理器，搜索是否存在多余的 `LLM串口.exe` 进程，若有请“结束任务”；
  3. **物理热重插**：拔出 USB 串口模块，等待 2 秒后重新插入，点击软件界面刷新按钮并重试。

### F03 打开串口时单片机异常复位重启

- **现象描述**：点击【打开串口】或断开重连时，开发板上的 LED 闪烁，单片机从 Boot 重新启动，导致调试上下文丢失。
- **可能原因**：
  1. 许多带有自动下载电路的开发板（如 NodeMCU、ESP32-DevKit、部分 Arduino）使用 USB 转串口芯片的 `DTR` 和 `RTS` 硬件引脚控制单片机的 `EN` (RST) 和 `IO0` (BOOT)；
  2. 操作系统在打开物理串口时，默认将控制线拉低，触发了单片机的硬件复位。
- **排查与解决步骤**：
  1. **硬件规避**：若无需通过该串口下载程序，可在开发板的 `EN` 与 `GND` 之间并联一个 1uF~10uF 滤波电容，或挑断复位电路的跳线帽；
  2. **使用纯串口引脚**：改用不带 DTR/RTS 自动下载电路的独立 USB-TTL 模块（仅连接 TX、RX、GND），避免复位信号引入。

### F04 串口已连接但无任何数据上送

- **现象描述**：状态灯已显示为绿色连接状态，但接收终端与波形画布没有任何新数据刷新。
- **可能原因**：
  1. 信号线接反：USB 转串口模块的 TX/RX 与单片机接线未交叉（应为 `TX -> RX`，`RX -> TX`）；
  2. 未共地：USB 转串口模块未与单片机系统共用 `GND`，导致信号电平无参考基准；
  3. 单片机未成功启动，或串口时钟初始化失败，程序卡死在 `HardFault` 或断言中；
  4. 下位机发送使用了 DMA 但未开启中断或传输计数器未复位。
- **排查与解决步骤**：
  1. **检查物理接线**：确保单片机 TX 接串口模块 RX，单片机 RX 接串口模块 TX，且两者 **GND 必须牢固直连**；
  2. **硬件自环测试**：断开与单片机的接线，将 USB 模块的 TX 与 RX 用杜邦线直接短接（自发自收），在软件常规调试模式下发送字符，观察能否收到回显。若能收到，说明软件与模块正常，问题在单片机侧；
  3. **单片机程序排查**：在单片机 `main()` 初始循环中增加一个 LED 翻转逻辑，确认内核未卡死。

### F05 终端接收文字乱码

- **现象描述**：接收区打印出的中文或英文字符变为乱码（如 `` 或生僻汉字）。
- **可能原因**：
  1. **波特率不匹配**：软件选择的波特率与下位机固件初始化波特率不一致（如固件为 115200，软件误选 9600）；
  2. **时钟频偏超标**：单片机内部 RC 振荡器（HSI）受温度影响温漂过大，或外部晶振配置频率与 `system_stm32.c` 的宏定义不匹配；
  3. **字符编码不一致**：下位机代码文件为 GBK 编码且发送中文字符串，而上位机终端采用 UTF-8 解码。
- **排查与解决步骤**：
  1. **核对波特率**：检查单片机代码中 `UART_Init` 的波特率参数，确保软件顶部波特率与其严格一致；
  2. **检查时钟树**：若使用外部晶振（HSE），务必核对硬件晶振频率（如 8MHz 或 25MHz）与工程配置宏是否完全相同；
  3. **切换编码与模式**：在软件接收区切换显示模式为【HEX】，观察原始字节流是否具备规律；推荐下位机调试日志统一使用 UTF-8 编码或纯英文字符。

### F06 有日志打印但画布无波形曲线

- **现象描述**：常规调试模式下可以看到文本打印，但切换到“AI波形调参模式”后，uPlot 画布无曲线绘制。
- **可能原因**：
  1. 下位机上送的数据格式不符合协议规范（缺少行尾 `\n` 或数值包含非法字符）；
  2. 格式混淆：采用了非标准文本包装（例如 `print("val=" + x)`），导致分流器判定为普通日志；
  3. 通道映射未生效：未在波形配置中正确勾选或指定数据通道。
- **排查与解决步骤**：
  1. **规范格式**：参考 [下位机对接指南](./firmware-integration.md)，将发送格式规范为标准 CSV（`target,actual,pwm\r\n`）或 Teleplot 格式（`>target:100\n`）；
  2. **确保换行符**：每一帧数据的末尾必须包含 `\n`，严禁在无换行的情况下持续推流；
  3. **检查通道映射**：在波形模式右上角打开【通道映射配置】，确认所需观测的通道处于激活勾选状态。

### F07 波形正常但未捕获“阶跃响应快照”

- **现象描述**：AI 波形调参模式能看到曲线实时滚动，但左侧快照列表始终为空，无法触发阶跃诊断。
- **可能原因**：
  1. 未在【通道映射配置】中指定**目标值 (Target)** 和**实际响应值 (Actual)** 两个核心物理通道；
  2. 目标值的跳变阶跃幅度过小（未达到系统内置的 $\Delta_{min} = 1.0$ 门槛），算法判定为噪声抖动；
  3. 目标值变化后，系统未进入稳定状态（波动持续超过 $\pm 5\%$），算法等待稳态超时放弃截取；
  4. 采用斜坡跟踪或高频正弦激励，而非阶跃响应测试场景。
- **排查与解决步骤**：
  1. **配置语义绑定**：点击【通道映射配置】，明确将 `target` 指定为目标通道，`actual` 指定为反馈通道；
  2. **增大阶跃测试阶差**：通过滑块或指令，下发一个明显的阶差（例如从 0 突变到 100）；
  3. **留足稳定时间**：阶跃后保持目标值恒定 2~3 秒以上，使被控对象充分进入稳态以触发快照截取。

### F08 自定义控件无法移动、缩放或删除

- **现象描述**：在“自定义控件面板”中，鼠标无法拖动卡片，右下角没有缩放手柄，点击右上角 `✕` 无反应。
- **可能原因**：
  - 当前处于 **🔒 运行锁定态 (Run Mode)**。为防止调参时误触破坏工控布局，系统在锁定态下隐藏了全部编辑手柄并禁用了布局修改。
- **排查与解决步骤**：
  1. 查看画布顶部右上角的挂锁图标；
  2. **鼠标左键点击挂锁**，切换为 **🔓 编辑中 (Edit Mode)**；
  3. 此时所有控件顶部将浮现拖拽把手，右下角浮现三角缩放手柄，可自由调整位置与尺寸；调整完成后再次点击挂锁保存锁定。

### F09 点击按键或滑动滑块，单片机无响应

- **现象描述**：在控件面板中点击按键或拖动滑块，串口已打开，但单片机没有任何动作响应。
- **可能原因**：
  1. 当前处于 **🔓 编辑态**（编辑态下控件交互默认屏蔽，防止配置布局时误触发指令）；
  2. 控件属性中配置的 `command_template` 指令模板与单片机固件解析格式不匹配；
  3. 报文末尾未配置换行符 `\n` 或 `\r\n`，单片机解析器一直在等待行结束符；
  4. 滑块被误配置为十六进制 HEX 模式但未填入合规指令。
- **排查与解决步骤**：
  1. **检查挂锁状态**：确保右上角挂锁已切换至 **🔒 运行锁定态**；
  2. **检查指令配置**：双击控件打开属性配置抽屉，检查指令模板是否带有 `\n`（例如 `SET_KP:{val}\n`）；
  3. **配合终端比对**：切换至常规调试模式，查看指令发送历史，确认上位机发出的原始字符串是否符合下位机 `sscanf` 的预期。

### F10 按下空格键急停无响应或未下发

- **现象描述**：发生失控时按下键盘空格键（Space），未触发急停下发。
- **可能原因**：
  1. 当前鼠标光标正聚焦在某个文本输入框或数字框内（输入框内空格键用于输入字符，避免误触急停）；
  2. 用户从未配置过急停报文（系统秉持 ADR 0004 规范，**绝不自动伪造未知的停机字节**，未配置时仅弹窗提示）；
  3. 物理串口处于断开状态。
- **排查与解决步骤**：
  1. **检查焦点**：点击画布空白区域释放输入框焦点后再次按空格键；
  2. **配置急停指令**：进入系统设置 $\to$【急停配置】，指定硬件匹配的急停报文（如 `ESTOP\n`）并保存；
  3. **明确安全边界**：软件急停通道受操作系统按键捕获与 USB 传输延迟限制，**遇险请优先拍下硬件物理急停开关或切断总电源**。

### F11 软件启动白屏或提示缺少运行组件

- **现象描述**：双击启动软件后界面纯白，或弹出提示缺少系统运行库。
- **可能原因**：
  1. 精简版 Windows 操作系统未安装 Microsoft Edge WebView2 Runtime；
  2. 杀毒软件（如 360、火绒或 Windows Defender）拦截了本机的无签名桌面进程；
  3. 解压目录处于带有超长中文路径或受权限保护的系统文件夹内。
- **排查与解决步骤**：
  1. **安装 WebView2 运行库**：前往微软官网下载并安装 [WebView2 Evergreen Standalone Installer](https://developer.microsoft.com/microsoft-edge/webview2/)；
  2. **添加信任区**：在杀毒软件拦截日志中将 `LLM串口.exe` 添加为信任白名单；
  3. **移动解压路径**：将整个便携文件夹移动到根目录英文路径（例如 `D:\tools\llm-serial\`）后重新尝试打开。

### F12 AI 智能分析网络请求超时或鉴权失败

- **现象描述**：在 AI 调参面板点击【AI 智能分析】后，长时间转圈或提示 `401 Unauthorized` / `Connection Timeout`。
- **可能原因**：
  1. 配置的大模型 API Key 无效、欠费或填写错误；
  2. API Base URL 填写有误（例如误加末尾多余的斜杠或缺少 `/v1`）；
  3. 本机处于无外网连接的封闭工业局域网中。
- **排查与解决步骤**：
  1. **检查网络与代理**：在浏览器中测试能否正常访问模型服务商的 API 域名；
  2. **核对 Base URL 与 Key**：进入 AI 配置面板，确认 Base URL 为兼容 OpenAI 规范的完整地址（例如 `https://api.deepseek.com/v1`），检查 API Key 无多余空格；
  3. **无网环境替代方案**：断网环境下请使用内置的【离线规则分析】模式，该模式基于经典控制理论完全本地运行，不消耗任何网络流量。
