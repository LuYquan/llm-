# 场景调参的异步执行归属

场景调参继续嵌在串口工作区中：协议解析出变量，用户核对通道、控制环、模型与约束，AI 或本地计算生成候选，再由本地执行规则管理发送、回执、反馈和停止。本文补充异步任务的归属与验收，不能替代设备验收。

## 本次问题

旧父界面在等待普通控件退出及驱动排空时只检查一个“调参忙碌”布尔值。停止 A 并开始 B 后，A 的迟到等待结果可能被当作 B 的授权结果。旧调参组件还允许在生成新候选 B 时发送旧候选 A；B 回包可能替换待确认轮次，导致 A 的实际写入与当前轮次脱节。

## 执行合同

- 每次执行都有唯一 `executionId`。开始、停止、参数发送及写入权限均绑定同一个 ID；旧任务不能授予、释放或覆盖新任务的权限和当前回执。
- 父界面在准备权限期间立即暂停普通发送；先等待普通控件退出，再等待真实串口驱动排空。每次等待都可取消。取消等待不会删除实际 pending/inflight 写入，也不会把旧等待的取消记为全局写入故障。
- 授权绑定连接、采集、解析代次及串口配置。即使之前已获授权，发送前仍核对上下文；上下文变化时撤销本次权限。
- 候选生成、建模、导入与设备执行共享组件操作归属。新候选请求期间不能发送旧候选，设备执行期间不能接纳另一个顶层候选或模型任务。
- 停止和卸载撤销本次操作并取消 AI 等待。取消不代表云服务撤回已接收请求，也不代表串口撤回已派发字节。实际写入仍由 transport 回执、排空状态和软件停止屏障如实记录。
- 真实迟到写入回执通过单独的记录输入送回原执行轮次，保留 request/session/epoch 和实际写入事实；它不能覆盖新执行的当前回执，也不能重建已撤销的基线或设备确认。
- 手动确认等待保留原执行 ID；确认后的采集仍属于该次执行。迟到响应、异常及 finally 只有在仍拥有操作时才能更新提示、会话或忙碌状态。

## AI 分工

TypeSafe 的小任务原则用于区分模型判断与确定性规则。Jev 可用于有明确类型输出、证据边界和本地校验的语义分类或路由；PID 计算、实验身份、互斥、授权、超时、回执关联和停止规则由本地代码执行。复杂建模和设计推理由 Codex/用户选择的模型承担。本次执行归属修复无需 Jev 请求。

本地兼容服务是否需要密钥采用与通用 AI 服务一致的判断。localhost、IPv4/IPv6 回环的兼容服务允许无密钥请求；远程兼容服务缺少密钥时在请求前拒绝。设置界面、调参预检与调参服务不应给出相互冲突的结果。

## 可执行验收

1. `npm run test:widget`：真实 lease coordinator 与 SendGate 的可控异步测试，覆盖旧 acquire/drain 成功、失败、异常、旧 finally、停止、身份重放及上下文变化。
2. `npm run test:write-queue`：取消旧 waiter 后真实 pending/inflight 仍存在，新 waiter 等待真实写入完成；正常超时仍保持失败关闭。
3. `node tests/browser/execution-lease-harness.vite.mjs`，在隔离 localhost:5200 打开夹具：实际 App、真实 WebSerialTransport、解析 Worker、本地 HTTP 响应及合成字节端口。通过真实控件尝试旧候选发送、停止 AI、放行迟到响应和再次执行，保存 HTTP/transport/会话记录与截图。
4. `npm run build:beta`：生成独立且可识别的 Windows 测试包；检查源码指纹、构建标识、清单、ZIP 内容及旧发布物保留状态。只发布核验后的源码到 GitHub，再核对远端提交与 Actions。

## 本轮实际 App 软件证据

已在隔离浏览器中使用真实 App、串口会话、Web Serial transport 和解析 Worker 验证两个分支。第一个分支在候选 B 等待响应期间禁止发送旧候选 A，取消 B 后放行迟到响应也没有参数写入。第二个分支取消正在等待 AI 的自动实验，再重新授权新实验；旧请求退出，新请求生成唯一候选，经合成驱动写入、精准 ACK 和新窗口采集后完成评价。两个最终分支合计 4 次本地 HTTP 请求、1 次合成参数写入、0 次 STOP 写入。

自动实验的成功分支通过真实控件选择了 5 秒遥测新鲜度时限；此前使用 0.5 秒时限触发保护的尝试单独保留，不算作成功取消。后台浏览器的定时器调度不能证明实机遥测频率，测试所选时限也不能作为平衡车或飞控的推荐安全时限。组件合成交互的时序条件与专门的遥测过期用例在夹具中分别声明；生产新鲜度保护未放宽。

组件夹具按回调间隔在 5 秒合同内补送有界的合成缓冲样本，并显式调用公开的 `ChannelStore.flushDispatch()` 派发订阅；超出合同不补送且判夹具失败。该方式避免依赖隐藏页面的 requestAnimationFrame 调度，只验证组件在收到声明输入时的行为，不证明实际 App、原生窗口最小化或后台采集的交付时序。实际 App 夹具使用原会话和 transport 路径，没有加入这项显式派发。

旧版本对照绑定 GitHub 提交 `a490136` 的 367 个源码文件，复现了“B 等待响应时仍能发送 A、B 响应替换当前待确认轮次”的问题。历史失败、超时、保护停止与最后通过的记录分别保存；源码指纹、浏览器证据、独立构建和远端提交通过本地交付清单关联。这里的端口字节与 HTTP 响应均为合成数据，没有真实设备或云模型调用。

浏览器合成端口验证软件链路；Windows 编译验证构建。本轮原生桌面交互、真实串口模块、固件 ACK、拔插、长期运行、物理急停、实机闭环、云 AI、干净 Windows、签名和许可证决定均需单独记录，未执行项不得标成发布通过。Rust advisory 警告不能因 Beta 构建成功而视为已处理。
