# 场景双路线与设备执行流程

本轮收敛场景调参的日常操作：选择调参路线和选择执行方式分别处理；重复选择当前选项不会重写配置或作废候选；模型计算先完成离线候选，再按需展开设备执行设置。实际交互检查使用独立来源的 `TuningWorkbench` 组件、合成遥测和本地 HTTP 响应，尚不构成原生或硬件验收。

## 两条调参路线

先在同一串口工作区的“AI 辅助 → 场景调参”选择平衡车、飞控或自定义套组，再选择控制方案、当前环节和控制器。

| 路线 | 需要的依据 | 日常操作 | 执行边界 |
| --- | --- | --- | --- |
| AI 遥测反馈 | 已核对的设备当前参数、范围、通道与单位，以及属于当前配置的观察窗口 | 在路线按钮下方明确选择“人工逐轮执行”或“有界自动调参”，核对候选依据、参数变化和最终命令字节 | 人工方式逐轮核对发送；自动方式须核对设备确认、预算、保护与范围，并授权本次实验 |
| 物理模型计算 | 已核对的物理数据或 s 域传递函数、输入输出方向、模型假设、固件采样周期与设计目标 | 确认模型后计算 PID 候选，先审阅本机结果；需要实机试验时再展开设备执行设置 | 不以模型计算结果代替设备生效、遥测评价或闭环稳定性证据 |

物理输入和手填传递函数的 PID 求解使用本机工具，无需配置在线 AI 服务。AI 服务入口仅在遥测反馈或“描述对象，让 AI 草拟模型”时显示。AI 草拟的模型、物理输入表和假设仍需用户核对，不自动取得设备写入权限。

控制方向、采样周期、剪切频率和相位裕度保留在模型计算设置中。串口变量、设备当前值、参数边界、试验目标与预算、命令及生效确认集中在“设备执行设置”，模型路线默认折叠，计算前无需填写这些执行字段。新场景、导入套组、激活其他环节及真实路线切换会复位该父层的展开状态，保留已填写配置。

## 选择与确认的状态规则

- 重复选择当前路线、场景、控制方案、控制器、模型来源或设备确认方式直接返回，不重写模式、模型确认或设备基线。已生成候选保持原有身份与状态。
- 真实路线或配置变化仍会使不再匹配的候选作废。需要重新生成、核对依据和发送字节，不能用界面切换恢复旧候选的执行权限。
- “逐轮人工核对”强制使用人工执行，并禁用“有界自动调参”选项。切换为参数变量回传或带本轮 ID 的 ACK 只改变确认方式，不自动开启自动执行；用户须再明确选择自动方式。
- 离开反馈路线时，用每个 `plan.id` 对应的面板内 Map 记住反馈执行方式。返回反馈路线时，人工确认始终使用人工方式；其他确认方式恢复该计划此前选择，未知偏好默认人工方式。该 Map 仅存在于当前面板生命周期，不是跨重新挂载或重启的持久化偏好。
- 忙碌状态下不接受路线、模型来源等设置切换；发送与试验继续检查候选签名、写入条件、设备确认和遥测依据。

模型候选结果标明“本机模型计算”，连接状态与候选来源分别呈现。尚未配置设备基线时，参数对照中的左列 `0` 只是计算参考。结果页提示首要设备试验待完成项；“查看设备试验设置”会返回设置页，并展开父层及串口变量、参数边界、目标与确认三个子区。

页脚的模型计算缺项入口显示“查看计算配置”，返回计算设置，不自动展开设备字段。反馈缺项入口显示“展开执行配置”，展开相关执行区域。折叠按钮可点击切换；本轮实际键盘检查仅覆盖 Enter 展开，不代表完整键盘或无障碍验收。

## 可执行复现

在工作区根目录、安装锁定的前端依赖后运行：

```powershell
node tests/browser/scenario-flow-harness.vite.mjs
```

浏览器打开 `http://127.0.0.1:5196/tests/browser/scenario-flow-harness.html`。该来源独立于正常应用；夹具挂载实际 `TuningWorkbench` 组件，合成数值经过实际 FireWater 解析与通道缓存。它只重置该来源的夹具调参存储键，不访问开发机 `data/` 或 `release/data/`。夹具本地 HTTP 只接受合成模型与合成会话请求，不是云端模型服务。

离线计算复现：

1. 顶部选择“离线模型 · 无设备配置”，点击“载入合成配置”。检查物理模型计算路线已选，设备执行设置折叠，AI 服务入口不显示。
2. 使用夹具提供的 `G(s) = 1 / (0.5s + 1)`、`PI`、正向控制、采样周期 `0.01 s`、纯延迟 `0 s` 和相位裕度 `60°`，核对并确认模型。剪切频率先保持 `1 rad/s`。
3. 点击“计算 PID 候选”。该目标在当前求解器中没有正增益 PI 解，应显示“当前模型无法求解”，不生成候选，也不自动更改设计目标。
4. 用户将剪切频率明确改为 `2 rad/s`，再次计算，才生成本机候选。本轮记录为 `Kp ≈ 0.406835319982`、`Ki ≈ 2.70886324676`、`Kd = 0`；这些是该模型与目标下的计算结果，不是平衡车或实机的推荐参数。
5. 返回设置页，重复选择当前场景、控制器、模型来源和路线，检查模型确认与候选保留。进入候选页，点击“查看设备试验设置”，检查父层和三个子区均展开；可以再折叠父层，并通过 Enter 展开。

反馈与模式复现：

1. 顶部选择“有效单次阶跃”，载入合成配置。展开“当前参数与写入边界”，勾选核对设备当前值，再点击“补充合成窗口”。
2. 在“人工逐轮执行”下点击“生成本轮 AI 候选”，核对摘要范围后确认。请求仅到当前来源的本地 HTTP 夹具，候选不下发。
3. 返回设置页，重复点击已选“AI 遥测反馈”，检查人工执行、人工确认和候选均未改变。真实切换到模型路线，检查人工确认仍保留，旧反馈候选作废。
4. 在 FireWater 的设备确认设置中选择带本轮 ID 的 ACK，检查仍为人工执行。用户明确选择“有界自动调参”后，切到模型再返回反馈，检查此前自动偏好恢复，同时缺失的执行条件继续阻止启动。
5. 改回人工确认，检查退出自动模式且自动选项禁用；再次选择 ACK，仍需用户明确选择自动执行。使用反馈缺项入口检查三个执行子区均展开。

不要点击发送或启动自动试验。夹具写入 handler 会记录并拒绝发送；本轮验收仅检查这些入口的禁用状态和设置流程。
