# LLM串口产品与技术路线图

> 更新：2026-10-01；当前源码版本：`0.1.1-beta.1`。本路线图以 [README](../README.md)、[产品定位](../PRODUCT.md)、[界面规范](../DESIGN.md)和已保存的软件验收为依据，不把源码存在、构建成功或公开提交称为正式发布。

## 场景与两条调参路线

入口顺序为“场景 → 控制方案与当前环节 → 控制器 → 调参路线”。平衡车支持直立环及直立／速度串级；飞控先按单轴角速度环，再处理姿态外环；自定义逐级配置 P／PI／PD／PID。使用受支持的拓扑，不假设整车、多轴耦合或空中联调已完成。

| 路线 | 所需依据 | 结果与执行边界 |
| --- | --- | --- |
| 物理模型计算 | 已核对物理字段或 s 域传递函数、输入输出关系、控制方向、采样周期、假设与设计目标。质量、半径等字段不能独自确定 PID。 | 本机离线计算候选，先审阅；设备试验设置按需展开。AI 草拟模型仍待确认，预测不生成实测对照或设备授权。 |
| AI 遥测反馈 | 当前设备参数、参数范围、通道与单位、当前配置对应的完整观察窗口，以及写入和确认协议。 | 明确选择人工逐轮执行或有界自动调参；ACK／参数回读不会自动开启自动方式。有界自动实验还需预算、保护、停止配置和本次显式授权。 |

继续遵循“配置 → 候选 → 授权 → 写入 → 设备确认 → 反馈评价 → 停止／复核”。配置、会话、内环来源或执行归属变化时，旧候选与不再匹配的依据失效。自然语言不能扩大权限，历史记录和导入套组不能恢复设备确认。具体流程见[双路线与执行流程](SCENARIO_FLOW_2026-10-01.md)、[串级依赖](SCENARIO_CASCADE_2026-10-01.md)和[单次阶跃条件](STEP_RESPONSE_ACCEPTANCE_2026-10-01.md)。

## 实施顺序与交付门槛

1. **收敛现有模块。** 串口会话和传输层管理字节、身份、队列及回执；记录与分析保留数据来源；本地调参服务管理候选、授权、确认和评价；AI 只提供声明范围内的建议。界面沿用共享工作区与渐进展开，复核高级页、键盘、浅／深主题和 125%／150% 缩放，不继续增加平行配置入口。
2. **完成原生与设备验收。** 绑定 EXE、源码摘要、固件版本、协议和试验条件，核对真实串口拔插、ACK／参数回读、长期采集、后台交付、保护停止与逐环闭环效果。平衡车和飞控分别保留受控台架证据；不得从软件通过推断实机达标。
3. **完成实际模型服务验收。** 分别验证本机 Ollama 与所选在线服务，记录证据上传范围、候选质量、无效输出、取消与服务故障。模型服务可用与闭环效果是不同结果。
4. **通过正式发行门槛。** 产品许可证、资源权属和依赖许可审阅由所有者／维护者完成，保留版本与 checksum 绑定的决定和通知材料。固定 RustSec 数据库的普通扫描曾报告常规漏洞 0、告警 7；严格公告门槛仍失败，严格许可也未通过。Beta 构建、CI、普通扫描退出 0 或源码公开均不等于许可和告警已解决。再完成干净 Windows、签名及发行材料复核。详见[依赖许可](DEPENDENCY_REVIEW_2026-10-01.md)和[控制与依赖记录](CONTROL_AND_DEPENDENCY_HARDENING_2026-10-01.md)。

每轮只对实际执行过的检查记录通过，保留失败、未运行项、输入摘要和产物哈希。修改冻结版本后重新建立关联；源码测试、浏览器合成、原生交互、硬件和用户验收分别记录。

## 后续规划

BLE GATT、TCP／UDP、CAN／CAN-FD、Linux／macOS 原生分发，以及新增连续控制控件，均属于后续选项。先核实真实使用需求、协议、维护和安全成本，再单独确定范围；目前不设承诺版本。优先复用声明式场景套组、工作区和协议样本，分享与导入不携带密钥、用户记录或设备授权，也不执行任意第三方代码。

贡献步骤见 [CONTRIBUTING](../CONTRIBUTING.md)。新能力需要说明入口、适用前提、已执行的软件检查和仍待完成的原生／硬件／服务验收。
