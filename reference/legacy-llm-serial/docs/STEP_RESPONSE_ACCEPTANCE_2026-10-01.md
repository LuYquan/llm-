# 场景反馈的单次阶跃与候选状态

本次修复 AI 反馈前的窗口资格判断。原评价仅使用首尾设定值与响应极值，多次目标跳变也可能被算作一次零超调阶跃。例如设定与反馈都为 `[0,0,0,0,0,1,0,1,0,1,1,1,1,1,1]`，输出全为 1，旧算法能够返回达标。修复后该窗口被拒绝，用户可分开采集，或明确使用轨迹跟踪目标。

## 日常流程

1. 在串口工作区选择场景、控制环节和 AI 反馈方式，绑定设定值、反馈、输出及单位。
2. 核对设备当前参数及写入边界。选择阶跃目标时，填写“阶跃设定值容差”：单位与设定值相同，`0` 表示精确相等。它描述设定平台的波动，和反馈的“最大稳态误差”分别填写。容差必须小于本次阶跃幅度的一半。
3. 采集含初始平台、一次跳变和最终平台的观察窗口。前后各至少 5 组平台采样，全部阶跃前反馈须处于初始目标的稳态误差范围内。
4. 点击生成候选。无效窗口在打开 AI 摘要授权前拦截；有效窗口经用户核对接收端与摘要后请求候选。生成候选不会下发参数。
5. 候选页从顶部显示状态、依据、参数变化和最终写入字节。修改配置后旧候选显示“已作废”，顶部恢复“配置草稿”，移除该候选的发送入口；需重新生成并核对。

旧套组缺少容差时仍可读取，但不自动填入数值或获得执行权限。界面显示待填写，不能请求阶跃候选；补充后需重新核对基线并采集窗口。最大超调可以填写 `0`，表示本轮不允许任何测得的超调。

## 确定性评价

`identifyStepReference` 取前 5 点、后 5 点中位数作为两个平台中心。两平台容差带不得重叠，每个设定样本只能落在其中一个平台内，仅允许一次初始到最终的转换。渐变、第三目标、返回初始平台、恒定设定、非有限数字、平台样本不足和缺失容差都不作为单次阶跃。

超调仅使用跳变后响应，按上升或下降方向相对最终目标的超出量除以实际阶跃幅度，不以目标绝对值或任意幅度下限替代。轨迹跟踪允许重复目标，使用 RMS 误差且不制造阶跃超调。大窗口用循环求极值，RMS 用缩放平方和避免有限大数平方溢出；不可表示的派生指标拒绝进入评价或 AI 请求。原始数组不被修改。

输出上限在阶跃分类之前检查。已识别的越界不能因为窗口格式错误被普通“数据不足”遮住，组件会请求本地发送屏障与已配置的停止命令。该行为不证明设备收到命令或停机。有限样本与平台资格也不证明平台持续时间、设备时钟精度、闭环稳定性、固件离散实现一致或硬件安全。

## 可执行复现

```powershell
npm run test:tuning
node tests/browser/step-response-harness.vite.mjs
```

浏览器打开 `http://127.0.0.1:5195`。夹具挂载实际 `TuningWorkbench` 组件，合成数据经过实际 FireWater 解析与通道缓存。它不是完整 App 集成或原生 WebView2 交互。仅清理这个独立来源的夹具调参存储键，不访问开发机 `data/` 或 `release/data/`。

在顶部选择案例、载入合成配置；展开“当前参数与写入边界”，勾选核对基线，再点“补充合成窗口”和“生成本轮 AI 候选”。有效案例需确认摘要；请求只到该来源的本地 HTTP 夹具。最后点击“记录当前证据”，可检查候选状态、请求摘要、本地停止事件和写入次数。不要点击发送按钮；写入 handler 计数并拒绝任何发送。

本轮执行的确定性行为检查共 27 项，包含上下行阶跃、负目标、重复跳变、斜坡、容差与旧配置、严格零超调、未稳定前平台、越界优先、大数、小单位、20 万点窗口、导入及服务边界。最终实际浏览器矩阵为 10 项：四类无效窗口、旧配置待填写、显式零容差修复、有效候选未下发、切页滚动归零、修改容差作废旧候选，以及重复目标使用跟踪路线。实际视口仅 1280×720；最终加载后的运行告警与错误为 0。

三个不同合成模型会话各有一次本地 HTTP 请求，所有设备写入为 0。外部 AI 请求与 Jev 调用均为 0；本地 mock 不冒充任何在线模型。按 TypeSafe 工作边界，数值资格、范围、窗口身份及停止由确定性代码负责，复杂实现由 Codex 完成。本会话此前的外部 Jev 源码摘要请求被自动审批拒绝，本轮没有重试上传或绕过审批。
