# 数据侧栏的通道身份与缓存状态

数据侧栏应回答“收到的是哪个通道、当前缓存有没有可显示的值、图表还在等待什么”，不把预设编号、持久化配置或历史读数当作正在收到的数据。本轮收敛侧栏状态与别名恢复，并用独立来源的实际 App 夹具验证。文档冻结时，最终浏览器结果、独立构建、源码提交和 CI 由主任务验收回执另行确认。

## 显示规则

`sidebarProjection.ts` 将缓存读数与明确配置的等待绑定分开。已接收集合必须有最近样本；仅分配了空缓冲或只有历史元数据不会变成已接收数值。侧栏读取元数据只用于显示，不因为渲染或轮询而创建持久化通道配置；用户明确配置通道时才进入存储修改。

| 输入状态 | 侧栏含义 |
| --- | --- |
| 最近原始值及显示变换均有效，包括原始 `0` | 当前会话运行时显示“缓冲读数”；停止时显示“已停止 · 缓存读数” |
| 最新原始样本为 NaN / Infinity，或 scale/yOffset 类型非法、变换结果溢出 | 显示“无有效显示值”和 `—`；不沿用旧值，不把字符串或缺失值隐式转换成零 |
| 当前活动页明确绑定、尚无最近样本 | 收入默认折叠的“已配置，等待数据（N）”集合 |
| `auto_bind=true` 的图表 | 无论保存的 `series` 是否为空，均不据其生成等待绑定，不展示猜测的 `0…7` 通道 |
| 清空单通道或全部显示缓存 | 清除对应当前读数；仍存在的活动页明示绑定可继续等待数据 |
| 串口/演示停止且缓存保留 | 可显示停止后的缓存读数；它只代表主机缓冲，不表示设备在线或采样新鲜 |

等待集合仅来自活动页的明示字段：非 auto-bind 图表的 `series[].channel`；gauge/number/led/stat_card 的 `channel`；slider/knob 的 `feedback_channel`；step_card 的 `actual_channel` 和字符串 `target_channel`。它不从所有 metadata key、App 的默认控制映射或其他页推断；没有额外的数据新鲜度推断。

显示名称保留真实通道身份。持久化配置以 canonical ID 为 key，`name` 为显示别名；重新加载后由实际工作区加载流程恢复别名，不由测试夹具临时注册。canonical ID 和 alias 查询同一底层缓存，显示、绑定与数据读取不创建额外 alias 缓冲；歧义或冲突不能任意选取目标。

侧栏显示别名冲突数量，并建议改为唯一名称或使用 canonical ID。原始单位与显示缩放配置弹窗增加名称输入，可通过键盘打开并修改，不必依赖双击重命名。解决冲突后仍须核对实际绑定身份，不能把更名当作数据来源确认。

待接收曲线和无效显示值还需要在绘图库边界作为 `null` 缺口处理，避免 NaN 污染坐标轴而使其他有限曲线消失；这仅作用于绘图数据，不把原始缺测值改为零，也不改变原缓存、原始单位或 AI/分析输入的有效性检查。该显示边界修复的最终浏览器结果以冻结回执确认。

实际浏览器还复现了全局隐藏/显示或重置显示配置后的 `s.stroke is not a function`：动态颜色更新须保留 uPlot 运行时 stroke 回调，修复前日志保存在本轮材料的 `runtime-errors-before.json`，修复后的实际交互以最终回执确认，不作为原生或硬件验收。

侧栏菜单收敛到当前已收通道的显示比例/偏置重置。去除侧栏手动创建零数据通道、含义不清的无数据清理及按索引假定跨通道时间对齐的批量 CSV 导出。需要导出波形时继续使用图表自身的范围导出流程；本轮没有新增跨通道同步导出验收，不增加侧栏的平行流程。

## 实际 App 合成夹具

在项目根目录、依赖已安装的情况下运行：

```powershell
node tests/browser/channel-sidebar-harness.vite.mjs
```

打开 `http://127.0.0.1:5194/tests/browser/channel-sidebar-harness.html`。必须使用这个独立 localhost 来源，不能在用户日常页面执行种子脚本。服务器使用实际 App、侧栏、图表、工作区加载和传输 session；合成 driver 仅通过透明按钮发送外部批次或状态。没有 native UI、真实串口、在线模型和设备写入。

夹具只在首次打开自身来源时写入合成工作区：canonical `actual` 名为“姿态角”，单位 `rad`/`user`；活动图表绑定 alias“姿态角”、canonical `speed` 和尚未接收的 `pending`。夹具不调用 `setAlias`，因此 reload 检查真实加载流程是否恢复映射。普通页面重载保留已经保存的合成工作区；“重置夹具配置并重载”仅重置该来源的两个指定 fixture/dashboard 键并重新种子化。

修复前界面读取别名可能额外写入同名 metadata key，造成与真实通道的 `name` 冲突。先保存这种配置和 DOM 作为旧副作用证据，再通过上述透明重置按钮恢复规范合成种子，进行修复后的 fresh/reload 验证；不能让夹具手动注册 alias 或猜测删除真实工作区中的歧义字段。

“记录侧栏证据”只读 `getBuffer(...,false)`，不会因为取证而分配缓冲。机器 JSON 包含实际 DOM 行、canonical/alias 查询的解析 ID、底层缓冲对象编号、点数、latest 值类别、缓存世代、会话身份、元数据、明示图表绑定和外部事件日志。`declaredAliases` 逐项记录当前持久化名称及其 targetId、解析身份和缓存编号，可核对更名后的 reload；`aliasConflicts` 只读记录实际冲突。NaN/Infinity 单独记录 `kind`，避免 JSON 默认把它们变成 null 而掩盖输入类型。

按以下顺序执行并保存 DOM、JSON 和截图：

1. 刚打开页面，展开实际 App 数据栏，检查没有合成接收前不捏造当前零值。初始图表有三个明示等待绑定，等待集合默认折叠，可用带 `aria-expanded` 的按钮展开。旧实现的默认编号行和“0”读数应作为修复前证据保留。
2. 点实际 App 顶部“演示”，再点“首个合成批次”。`actual` 收到 `[1,2]`、`speed` 收到 `[3,4]`，两者应显示缓存读数；`pending` 继续等待。图表 alias“姿态角”和 `actual` 应查询同一缓冲，不能多出 alias 或默认编号缓冲。
3. 点“合成真实零值”，确认最近 `0` 是有效样本而非空数据占位。点“合成非有限值”，确认最近 NaN/Infinity 显示“无有效显示值”和 `—`。原始样本非法、显示 scale/yOffset 为非法类型或变换溢出应分别验证，不允许隐式转换成零。这是合成故障验证，不证明设备协议允许这些数值。
4. 分别点“清 actual 显示缓存”和“清全部显示缓存”。已清通道不保留旧当前值；活动页绑定仍可等待。再发有限批次可恢复读数。
5. 点“新身份批次”。App 应先清旧显示缓存再写新 session/epoch，侧栏、图表与机器身份一致，不能混合旧身份样本。
6. 点“合成驱动断开”。保留的读数应标为“已停止 · 缓存读数”；不能宣称设备在线、最近仍收到数据或设备已执行停止。
7. 等实际配置保存完成后重载页面，再点击实际 App“演示”和“首个合成批次”。无 fixture `setAlias` 的条件下核对 alias 恢复、canonical 缓冲共用、原始单位和等待集合。另行核对实际导入工作区的歧义/冲突数量及提示，并用可键盘访问的原始单位/缩放配置弹窗修改名称，核对唯一名称或 canonical ID 修复后的绑定。
8. 在暗色、浅色和不同尺寸核对侧栏展开、等待折叠、配置弹窗及读数含义；有限曲线与待接收/无效曲线并存时核对坐标轴和缺口显示，不能只隐藏待接收曲线后认定修复。每次“记录侧栏证据”都应满足 `writeAttempts=0`。

夹具启动不等于交互通过，源码中的用例也不等于实际验收结果。本次材料保存在 `output/channel-sidebar-20261001/`；该目录不随源码发布。

