# AI 调参实验工作区 v1：使用说明与实现边界

本文对应源码中的独立“AI 调参”工作区。它与日常串口画布共用连接、遥测通道和日志，但实验计划、候选、设备确认和试验记录由调参工作区维护。

## 适用范围

首版面向嵌入式开发者的单环 PID 与已有串级环路。它提供两条候选路线：

- **对象模型计算**：使用用户录入的受控对象模型、控制结构、采样周期和频域目标调用本机数学求解器；缺少模型或约束不合格时不给出实机候选。模型计算结果仍需审阅和实测。
- **遥测反馈建议**：将项目说明、提示词、控制配置、参数范围和汇总后的遥测指标发送到用户配置的 AI 服务。原始串口日志和完整波形不随请求发送。服务不可用、响应无效或候选越界时停止并说明原因，不回退到固定示例参数。

AI 候选、本机计算候选、设备写入确认和遥测评价是不同证据。工具记录关联输入指纹、执行时间和候选结果；模型文本本身不构成工具执行或设备验证证据。

## 操作流程

1. **任务**：填写实验与项目名称、对象/工况说明，选择模型计算或遥测反馈路线，并为 AI 提供可编辑的项目提示词。
2. **控制结构**：选择已有控制环、P/PI/PD/PID 结构、控制方向、采样周期和参数写入命令模板。控制方向要依据真实执行器与反馈关系核对。
3. **设备通道**：将已有遥测通道绑定到设定值、反馈、输出和可选参数回读；手工填写并核对工程单位。当前版本不做单位换算，设定值与反馈单位必须一致。参数通道可用来读取基线，也可作为写入确认。
4. **基线与目标**：手工填写当前参数或从参数通道读取后，再明确确认设备当前生效值。工程模板中的数值只是参考。逐项设置参数边界、单轮变化比例、观察时间、最大试验轮数、输出限值和评价目标。
5. **候选与试验**：模型路线可以在离线配置时生成候选；反馈路线需要新鲜遥测。逐轮模式先显示候选、依据和命令，发送前二次确认。若设备没有自动确认能力，发送后等待用户在设备或仪器侧核实，再手动确认。
6. **范围内自动模式**：仅允许在确认现有基线可稳定运行、参数有硬边界、设备提供应答或参数回读，并设定停止条件后启用。启动前会展示授权摘要；运行中停止试参、异常或断连会暂停。自动模型路线只写入一个计算候选，反馈路线最多运行配置的轮数。
7. **复盘**：记录区区分候选、已发送、已确认、已评价、失败和用户忽略。只有收到写入确认并完成当前评价窗口，才把遥测结果记为实测指标。达到目标仅对本次计划中填写的目标和观察窗口成立。

## 实验安全与证据边界

- 桌面端负责候选范围、单轮变化、连接/遥测新鲜度、串口写入权、应答等待和记录；实时控制与最终输出保护仍须由设备固件负责。
- 设定值、反馈与输出单位由用户在任务中填写，控制参数单位/公式按固件实现标注。当前版本不会自动换算异单位通道。
- 没有应答或参数回读时，系统显示“生效状态未知”并暂停；不把“已发送”当成“已生效”。
- 异常停止只代表调参器不再继续发送试参。除非设备协议实际确认，否则本软件不宣称已恢复参数、已停机或已触发硬件保护。
- 本地工作区默认在新会话重启后将待确认/采集状态恢复为暂停。套件导入只导入声明式 JSON 配置，不会执行代码、发送命令或启动实验。
- 当前没有社区商店、第三方任意脚本执行、自动固件回滚或通用硬件安全阈值。
- 连接抽屉中的 DTR、RTS 与 Break 仅在提供 `setSignals` 的 Web Serial 驱动下可用；当前 Windows Tauri 桌面驱动没有实现这些物理信号操作，因此界面明确禁用。调用成功只表示驱动接受了设置，目标板的电气行为尚未经过硬件验收。

## 项目套件

工作区可导入或导出 `.llm-tuning.json` 声明式套件，内容包括兼容信息、项目提示词/知识、已注册工具标识和调参配置。设备基线、API Key、日志及试验历史不随套件导出。导入后应用会清除设备当前值与自动授权，用户仍需检查命令、模型、通道、单位、参数边界和设备保护条件。

## 本次实现验收记录

- `npm run build`：Vue/TypeScript 检查与 Vite 生产构建通过。构建仍报告 AI/Tauri 动态与静态导入混用、主 bundle 超过 500 KiB 的既存架构警告。
- `npm run test:tuning`：调参预检、候选边界/步长、静态/阶跃/跟踪目标、输出超限、设备回读、会话恢复与套件校验通过。
- `npm run test:widget`：现有 Phase 0–5、控件、Copilot、控制工具链、通道绑定与 UI 简化测试通过。测试脚本使用 Node 22.6+ 原生类型剥离，不通过 `npx` 下载执行器。
- `npm run test:transport`：桌面/网页传输契约、Web Serial 信号能力探测与 DTR/RTS/Break 调用映射通过；不替代实际浏览器或硬件测试。
- 本地开发页面此前已打开检查调参工作区布局；最终代码修改后的截图复核受 CUA 浏览器连接失败影响。开发服务器返回 HTTP 200，构建与空数据保护代码通过，但本条不宣称已完成人工鼠标全流程走查。
- 真实发布版 `D:/Desktop/LLM串口/release/LLM串口.exe`、物理串口和控制对象未在本轮最终变更后走查；因此没有桌面 EXE、硬件稳定性或端到端调参效果结论。

## 后续执行顺序

1. **可信性修正**：覆盖离线伪候选、来源冒充、发送/确认混淆和无采样绘图。
2. **工作区闭环**：扩展实验配置兼容性、恢复、失效规则和按任务/项目分类的评价策略。
3. **协议适配**：围绕具体固件验证命令格式、回传时间戳、确认应答和断连后的恢复策略。
4. **套件管理**：补充套件作者/版本编辑、兼容迁移和本地安装管理；社区目录需要单独审核与安全设计。
5. **分级验收**：依次完成源码和自动化检查、仿真数据验证、发布版 UI 走查、限能实机测试和各项目工况验收；每一级单独记录，不互相替代。
