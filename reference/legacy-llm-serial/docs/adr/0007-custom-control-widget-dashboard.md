# ADR 0007: 引入类似 VOFA+ 的自定义控件工作台架构 (WidgetDashboard)

- **状态 (Status)**: 已接受 (Accepted)
- **日期 (Date)**: 2026-09-25
- **决策人 (Deciders)**: 架构团队、使用者交互对齐

---

## 1. 背景与问题陈述 (Context)

在电机控制、PID 参数调试以及机器人现场排障过程中，工程师除了观察实时曲线（VOFA+ 模式）和收发文本指令（XCOM 模式）外，高频需要一种**“所见即所得的可视化操控台”**：
- 能够通过拖拽**滑块 (Slider)** 实时调整目标转速或 PID 增益，而无需手动反复敲入长串命令；
- 能够通过点击**动作按键 (Button)** 快速触发标定、复位、启停动作；
- 能够通过**数值微调框 (Number Input)** 步进微调参数。

使用者明确提出增加类似 VOFA+ 的控件库需求，并在需求对齐中确定了第三工作台独立面板、首期核心交互元器件以及指令模板安全下发的架构要求。

---

## 2. 备选方案权衡 (Alternatives & Trade-offs)

### 方案 A：在现有波形或调试面板边缘挤压挂载
- **优点**：无需新增顶层 Tab 导航。
- **缺点**：界面空间拥挤，波形图视窗与控件同时显示会造成严重的空间争夺；且控件数量较多时布局受限，难以支持工程师自由增删定制。

### 方案 B（选定）：新增第三个独立主工作台【自定义控件面板 (WidgetDashboard)】
- **方案描述**：
  1. 在顶栏双模切换器（常规调试模式、AI波形调参模式）基础上，扩展为三模切换体系：增加【自定义控件面板】；
  2. 采用响应式可配置卡片网格布局，支持使用者自由【添加控件】、【配置参数】、【拖拽排布】与【导出/导入配置】；
  3. 首期重点打造两类核心高频控件：
     - **滑块调参器 (SliderWidget)**：设定 Min / Max / Step / 物理单位，拖拽松开或连续拖动时按模板下发；
     - **动作按键与微调框 (Button & NumberInput Widget)**：设定触发指令与增减步进量；
  4. 采用**参数模板语法**（如 `SET KP={val}\n` 或 `target={val}\n`），变量动态插值渲染；
  5. **安全闭环**：所有由控件触发下发的参数，与 AI 建议下发链路一样，统一接入 `SafetyGuard` 本地限幅校验，防止滑块拖出极端暴走参数导致电机飞车。

---

## 3. 决策内容 (Decision)

1. **三模中枢架构**：系统工作模式正式扩展为三大工作台：
   - 【常规调试模式】(XCOM 超集)
   - 【AI波形调参模式】(VOFA+ 超集 + LLM 自整定)
   - 【自定义控件面板】(可编程交互中控台)
2. **元器件配置抽象**：定义统一的 `WidgetConfig` 结构，支持保存在工作区持久化配置（`app_config.json` 或 `localStorage`）中，确保重新打开时布局不丢失。
3. **安全守护集成**：控件变动下发的参数指令，继承系统的 `SafetyGuard` 物理限幅规则，在极值和 NaN 异常时拦截报警。

---

## 4. 影响与后续规划 (Consequences)

- **正面影响**：
  - 工具能力对齐并超越传统 VOFA+，工程师调试硬件时拥有兼具“波形分析、AI诊断、交互按键、滑块控制”的完整闭环。
- **技术债务与成本**：
  - 需要设计并开发 `WidgetDashboard.vue` 及对应元器件组件（`SliderWidget.vue`、`ButtonWidget.vue`、`NumberInputWidget.vue`），并在后续阶段逐步支持更多如仪表盘（Gauge）与 LED 指示灯等回读类元器件。
