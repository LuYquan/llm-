# ADR 0005: 通道语义绑定与阶跃快照事件流

- **状态 (Status)**: 已接受 (Accepted)
- **日期 (Date)**: 2026-09-22
- **决策人 (Deciders)**: 架构师团队、产品设计团队

---

## 1. 背景与问题陈述 (Context)

在早期的 PRD 方案中，存在两个阻碍“自动特征提取”与“AI精准分析”的致命盲区：
1. **通道身份不透明**：单片机传输的 3 条曲线，Rust 和算法引擎并不知道哪条是 Target (目标设定值)，哪条是 Actual (实际响应)，导致无法计算超调和调节时间。
2. **分析时机难抓取**：实时波形以 60FPS 不断滚动，如果由用户主观随意点击“请求 AI 分析”，极易捕捉到不含有效阶跃激励的平缓数据，产生 AI 幻觉和垃圾建议。

---

## 2. 决策内容 (Decision)

为了构建真正稳定可靠的大模型分析闭环，引入以下两项关键机制：

### 2.1 交互式通道语义绑定 (Semantic Binding)
- 不强制规定单片机端 `printf` 的顺序或命名。
- 在前端界面（波形图例处或侧边栏顶部），提供针对通道的下拉框，供用户手动将某一条线绑定为 `Target`、另一条绑定为 `Actual`、第三条绑定为 `Output`。
- 绑定操作会即时同步到 Rust 后端的 `StepDetector` 引擎中。

### 2.2 自动快照记录流 (Event-Driven Snapshots)
- Rust 端的 `StepDetector` 持续监控被标记为 `Target` 的通道。
- 一旦检测到目标值发生阶跃突变，且 `Actual` 曲线跟随并进入新的稳态（或触发超时），Rust 在后台自动计算出各项指标，并生成一份静态的**阶跃快照 (StepSnapshot)**。
- 该快照被推送到前端，在侧边栏生成一张独立的【阶跃记录卡片】。
- 只有针对这些已固化的静态快照卡片，用户才能点击“请求 AI 诊断”进行分析，彻底避免了截图时机不对导致的数据错乱，并完美支持了多次参数实验的前后对比。

---

## 3. 影响与后续结果 (Consequences)

- **正面影响**：确保了输送给 LLM 的数据绝对是有效且高度结构化的“优质实验结果”；同时大幅降低了用户的使用心智负担，不必手忙脚乱地抓拍波形。
- **负面影响**：前端右侧边栏 UI 复杂度增加，从单一的静态面板变为一个类似于“实验时间线/瀑布流”的卡片列表。
