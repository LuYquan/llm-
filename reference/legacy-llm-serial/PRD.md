# LLM串口 — 产品需求文档 (PRD)

> **文档版本**: v2.0 (终极全能工作台版)  
> **更新日期**: 2026-09-22  
> **产品定位**: 面向硬件与嵌入式工程师的终极全能 AI 串口工作台 (The Ultimate AI Serial Workbench)  
> **核心理念**: **“硬件工程师的桌面上，只需要这一个串口助手就够了”**。

## 1. 产品目标与使用场景

### 1.1 产品目标与行业痛点

当前硬件与嵌入式开发者的桌面上普遍存在**工具割裂**的严重痛点：
- **XCOM / SSCOM / 丁丁**：日常收发 HEX、测 AT 指令、发定时包离不开它，但界面停留在 20 年前，没有波形，容易假死，无智能化。
- **VOFA+ / Serial-Studio**：波形渲染强大，但缺少传统助手的便捷快捷指令、HEX 调试与校验工具，想临时发个控制帧还要切回 XCOM。
- **AI 工具**：目前市面所有串口工具全是“被动哑巴软件”，遇到单片机死机报错（HardFault/Panic）或控制参数震荡，全靠工程师人脑翻手册试凑。

**LLM串口**致力于成为**集大成的总结性软件**：
1. **集众家之所长**：融合 XCOM 的日常收发便捷性 + VOFA+ 的极致波形渲染 + electerm 的现代化设计美学。
2. **补众家之所短**：解决传统软件界面丑陋、容易假死、配置繁琐的缺陷，提供原生的流畅体验与状态记忆。
3. **AI 全面融合赋能**：在日常调试中融入 **AI 故障日志诊断 (Log Explainer)**；在控制调参中融入 **AI 阶跃指标闭环诊断 (PID Auto-Tuner)**。真正做到一个软件覆盖硬件工程师从上电调试、报错排查到闭环调参的全生命周期。

### 1.2 设计北极星（五大原则）

| 原则 | 量化约束与体验标准 |
|:---|:---|
| **一站式 (All-in-One)** | 覆盖 95% 硬件开发日常（常规收发/HEX/校验/快捷指令/波形/调参），无需再开第二款串口软件 |
| **轻量高效** | 独立原生 `.exe` 安装包 ≤15MB，内存 ≤100MB，1kHz 数据流吞吐不卡顿 |
| **AI 深度融合** | 拒绝简单套壳，AI 针对硬件错误日志与阶跃响应指标进行高可信结构化诊断 |
| **零门槛兼容** | 单片机端 `printf` 零配置接入，支持 CSV/Teleplot，跨任何 MCU 平台 |
| **工业级稳健** | USB 拔插不闪退、单片机重启乱码不卡死、配置静默记忆、本地日志可追溯 |

### 2.2 底层串口数据架构（三级管道 + 智能分流）

```
┌─ 第一级：采集与智能分流 ─┐   ┌─ 第二级：数据管理与分析 ─┐   ┌─ 第三级：AI 与交互 ─┐
│ 串口/BLE 硬件 IO          │   │ 时序环形缓冲 (RingBuffer)│   │ 前端 UI 渲染        │
│ StreamDemuxer 智能分流    │──▶│ LTTB 降采样             │──▶│ 底部日志抽屉        │
│ ├── 数值波形行 (CSV/Tel) │   │ 阶跃特征自动提取        │   │ AI LLM 单轮调用     │
│ └── 调试日志行 (Log)     │   │ 日志环形缓冲 (LogBuffer)│   │ 安全校验 + 核准下发  │
└───────────────────────────┘   └─────────────────────────┘   └─────────────────────┘
         全部 Rust                        全部 Rust               TS(UI) + TS(AI)
```

**核心原则**：Rust 做所有"重活"（IO、解析、缓冲、分析），TypeScript 只做 UI 渲染与 AI API 调用。算法只在 Rust 端写一遍，前端通过 Tauri IPC 纯消费。

### 2.4 核心契约修订与 IPC 规范冻结 (PR-001)

#### 2.4.1 开工前六大工程边界
1. **115200bps 与 1kHz**：115200bps 8N1 有效上限约 11.5KB/s。1kHz 压测使用 Mock 或 ≥460800bps 串口；115200bps 验收使用短报文速率。不得把物理带宽不足记作软件丢包。
2. **≤15MB 安装包**：以 Windows NSIS `.exe` 安装包为测量对象，使用系统 WebView2 Runtime，不内嵌完整运行时。
3. **≤100MB 内存**：验收口径为**应用主进程及其 WebView2 子进程合计内存**。
4. **AI ≤5 秒**：本地 Mock AI 与正常网络作为性能目标。超时、失败或 JSON 无效时，5 秒内结束等待并展示离线建议，绝不下发。
5. **软件急停**：空格键和高优先级写队列提供尽力而为的串口急停，不能替代硬件急停或设备看门狗。
6. **日志“2000 行”与“不丢失”**：UI 和内存环形缓冲保留最近 2000 行；默认另行写入带轮转策略的串口归档文件。

## 3. 串口内容结构

### 3.1 上行数据（单片机 → PC）

第一版仅支持**纯文本协议**，两种格式自动嗅探：

**格式 A：逗号分隔（CSV）**
```c
// 单片机端一行代码
printf("%.2f,%.2f,%.2f\n", setpoint, actual, output);
```
输出示例：`10.00,9.23,30.15\n`

- 每行一个采样点，字段以英文逗号分隔
- 通道名默认为 `ch0`, `ch1`, `ch2`...（可在前端重命名）
- 自动识别规则：首行不以 `>` 开头，且包含逗号和可解析浮点数

**格式 B：Teleplot 键值对**
```c
// 单片机端
printf(">setpoint:%.2f\n>actual:%.2f\n>output:%.2f\n", sp, act, out);
```
输出示例：`>setpoint:10.00\n>actual:9.23\n>output:30.15\n`

- 每行一个变量，格式为 `>变量名:数值\n`
- 通道名自动从 `>` 后提取
- 自动识别规则：首行以 `>` 开头

**非数值文本日志**
```c
printf("[INFO] Motor Init OK\n");
printf("[ERROR] I2C Timeout at addr 0x68\n");
```
- StreamDemuxer 自动识别为非波形数据，路由至日志环形缓冲
- 在底部日志抽屉中带时间戳显示
- 不影响波形解析

### 3.2 下行数据（PC → 单片机）

**参数下发格式**
```
SET:KP=1.20,KI=0.05,KD=0.30\n
```
- 由工程师在 AI 核准下发时触发
- 单片机端需实现简单的字符串解析（参考嵌入式示例代码）

**快捷指令**
```
RST\n          // 重启
CALIB\n        // 校准
CMD:STOP\n     // 急停（由用户自行配置绑定内容）
```

**急停指令**
- 空格键触发，发送内容由用户在设置中绑定（默认未绑定）
- 未绑定时按键仅弹出提示，不发送任何字节

## 4. 每一个模块的作用

### 4.1 Rust 后端模块

| 模块 | 代码标识 | 核心职责 |
|:---|:---|:---|
| **数据源抽象** | `DataSource` trait | 统一硬件 IO 接口，封装串口/BLE/Mock 数据读取 |
| **串口数据源** | `SerialDataSource` | 基于 `serialport-rs` 的异步串口读写，枚举可用端口 |
| **Mock 仿真源** | `MockDataSource` | 内置二阶系统 PID 仿真器，无需硬件即可开发测试 |
| **智能分流器** | `StreamDemuxer` | 逐行扫描串口流，将数值行和日志行分别路由至不同缓冲池 |
| **协议解析器** | `TextParser` | 解析 CSV 逗号分隔 / Teleplot 键值对，输出结构化浮点数组 |
| **时序环形缓冲** | `TimeSeriesRingBuffer` | 固定容量环形队列，存储解析后的多通道时序数据点 |
| **日志环形缓冲** | `LogRingBuffer` | 固定容量文本日志队列（最近 2000 行），10Hz 节流推送前端 |
| **LTTB 降采样器** | `Decimator` | 当缓冲池数据量超过显示像素时，用 LTTB 算法降采样保留波形特征 |
| **阶跃检测器** | `StepDetector` | 监测 setpoint 通道突变，自动捕获观察窗口 |
| **阶跃特征提取** | `StepAnalyzer` | 计算超调量 $M_p$、调节时间 $t_s$、上升时间 $t_r$、稳态误差 $e_{ss}$ |
| **参数下发器** | `ParamWriter` | 将前端核准的 PID 参数格式化为 `SET:...` 指令写入串口 |
| **安全限幅器** | `SafetyGuard` | 校验参数极值（NaN/Infinity/符号反转），拦截异常值 |

## 5. 每个模块第一版最必要的数据和操作

### 5.1 常规调试模式：终端与收发 (GeneralTerminal)

| 字段 | 第一版最小要求 |
|:---|:---|
| **数据输入** | 串口原始字节流（转换为 ASCII 文本或 HEX 格式字符串）、带微秒级时间戳 |
| **用户操作** | 勾选 HEX 显示 / HEX 发送、清空屏幕、暂停滚屏、**点击报错行「💡AI 诊断此错误」** |
| **数据输出** | 格式化时间戳日志、AI 针对硬件错误（HardFault/Panic/I2C Error）的分析弹窗 |

### 5.2 常规调试模式：快捷指令与工具箱 (QuickCommandPanel)

| 字段 | 第一版最小要求 |
|:---|:---|
| **数据输入** | 用户自定义配置的多条指令列表（名称、内容、HEX/ASCII 标志） |
| **用户操作** | 单击发送单条指令、勾选循环定时发送（自定义周期如 100ms）、输入数据计算 CRC16 |
| **数据输出** | 向串口发送指定指令字符串/HEX 字节、实时计算出的 CRC16/Modbus 校验码 |

### 5.3 AI波形调参模式：实时波形 WaveformViewer

| 字段 | 第一版最小要求 |
|:---|:---|
| **数据输入** | Rust 60Hz 批量推送的多通道浮点数组（经 LTTB 降采样） |
| **用户操作** | 鼠标滚轮缩放时间轴、拖拽平移、**通过下拉框将通道语义绑定为 Target/Actual/Output** |
| **数据输出** | 当前可见窗口的时间范围、鼠标悬停处的精确数值、向下游输出语义绑定事件 |

### 5.4 AI波形调参模式：阶跃指标与快照流 (SnapshotStream)

| 字段 | 第一版最小要求 |
|:---|:---|
| **数据输入** | Rust 端在检测到阶跃完成后，推送的 `StepSnapshot` 事件（含 Mp, ts, tr, ess 等指标与波形切片） |
| **用户操作** | 浏览右侧边栏自动生成的“阶跃记录卡片流”，选择一张卡片点击「请求 AI 分析」 |
| **数据输出** | 固化的单次阶跃记录卡，作为传递给 AI 诊断的绝对数据源 |

### 5.5 AI波形调参模式：AI 调参卡片 (AiTunerPanel)

| 字段 | 第一版最小要求 |
|:---|:---|
| **数据输入** | **单一历史 `StepSnapshot` 快照数据** + 当前 PID 参数 + 被控对象类型 |
| **用户操作** | 查看针对该次快照的 AI 诊断结论 → 点击「核准下发」或「忽略」 |
| **数据输出** | AI 返回的诊断文字、推荐 Kp/Ki/Kd 新值（高亮变化量）、风险提示 |

### 5.5 品质雷达图 MetricRadar

| **用户操作** | 无主动操作，阶跃分析完成后自动刷新雷达图 |
| **数据输出** | ECharts 五轴雷达图渲染 |

| 字段 | 第一版最小要求 |

## 6. 串口、控件与大模型之间的关系

### 6.1 数据流全链路关系图

```
  ┌──────────┐
  │  单片机   │
  │ printf() │
  └────┬─────┘
       │ 串口字节流 (UART 115200)
       ▼
  ┌──────────────────────────────────────────┐
  │           Rust 后端 (Tauri)               │
  │                                          │
  │  SerialDataSource ──▶ StreamDemuxer      │
  │                        ├─ 数值行 ──▶ TextParser ──▶ RingBuffer ──▶ StepAnalyzer
  │                        └─ 日志行 ──▶ LogRingBuffer                      │
  │                                                                         │
  │  ParamWriter ◀── SafetyGuard ◀──────────────────── StepResponseMetrics ─┘
  └─────────┬──────────────┬───────────────────────────────────┬────────────┘
            │              │                                   │
     Tauri Event      Tauri Event                        Tauri Command
   (60Hz 波形批次)   (10Hz 日志批次)                   (get_step_metrics)
            │              │                                   │
            ▼              ▼                                   ▼
  ┌──────────────────────────────────────────────────────────────────────┐
  │                    Vue 3 前端 (TypeScript)                           │
  │                                                                     │
  │  WaveformViewer ◀── 波形数据          StepOverlay ◀── 阶跃指标      │
  │  LogDrawer ◀── 日志数据                                             │
  │                                                                     │
  │  AiTunerPanel ──▶ 构造 Prompt ──▶ LLM API ──▶ 解析 JSON 结果      │
  │       │                                              │              │
  │       │         TuningSuggestion {Kp, Ki, Kd}        │              │
  │       ▼                                              ▼              │
  │  用户「核准下发」──▶ SafetyGuard 校验 ──▶ invoke('write_params')    │
  └──────────────────────────────────────────────────────────────────────┘
            │
     Tauri Command (write_params)
            │
            ▼
  ┌──────────────────┐
  │  Rust ParamWriter │──▶ 串口写入 SET:KP=...,KI=...,KD=...\n
  └──────────────────┘
            │
            ▼
  ┌──────────┐
  │  单片机   │ 解析并应用新 PID 参数
  └──────────┘
```

### 6.2 三者关系的核心原则

| 关系 | 规则 |
|:---|:---|
| **串口 → 控件** | 串口原始数据必须经过 Rust 层解析/分流/降采样后才推送给前端控件，前端**绝不**直接读写串口 |
| **控件 → 大模型** | 前端 AI 调参卡片将 Rust 提供的阶跃指标打包为结构化 Prompt，直接调用 LLM API，Rust 不参与 AI 调用 |
| **大模型 → 串口** | LLM 输出的参数建议**必须经过人工核准（Approve）和安全校验（SafetyGuard）**才能写入串口，绝不自动下发 |
| **安全原则** | "Suggest, Do Not Commit"——AI 只建议，不执行；工程师拥有最终决定权 |

## 10. 工业级非功能性需求 (NFRs)

为了保证“原生软件”的质感，第一版必须严格满足以下工程规范：

### 10.1 异常处理与热插拔 (Robustness)
- **柔性重连**：硬件断开时（拔线、断电复位），后端安全捕获 `io::Error`，不发生 Panic。向前端推送断开事件，UI 顶部状态栏变红但**不锁死界面**，保留历史快照和图表供继续查看。
- **一键恢复**：检测到目标 COM 口重新上线后，提供“一键恢复连接”操作。
- **脏数据容错**：串口断电瞬态产生的乱码字符，解析器直接丢弃并统计 Error 数，绝不允许阻塞后续合规数据的解析。

### 10.2 全局状态静默持久化 (Workspace Persistence)
- 引入 `tauri-plugin-store` (或等效的 Rust 配置管理机制)。
- **被记忆的状态**：上次使用的串口号、波特率、AI API Key、Model 选择、目标/实际/输出的通道绑定关系。
- 每次改动后台静默落盘至 `%APPDATA%` (Windows)，下次启动软件自动恢复到关闭前一模一样的工作区状态，避免重复配置。

### 10.3 系统级日志与可观测性 (Observability)
- Rust 端引入 `tracing` 与 `tracing-appender`。
- **轮转文件机制**：每天生成一个运行日志（如 `llm-serial-2026-09-22.log`），保存在操作系统的应用数据目录，最多保留最近 7 天。
- 前端提供“打开日志目录”入口，方便非技术用户快速打包错误日志反馈给开发者。
